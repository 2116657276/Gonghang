## 1. 项目是什么

行止是一套青年消费规划应用：用户先建立资金事实与预算，再登记购买需求、比较候选商品、确认购买、跟踪订单和售后，并在计划变化时重新计算可支配金额。项目现阶段用于竞赛演示和本地联调，不代表已经接入真实银行账户或正式上线。

当前代码由以下部分组成：

- 消费者端：`xingzhi/apps/miniapp`，使用 Taro + Vue 3，同一套源码构建 H5 和微信小程序。
- 商户/审核端：`xingzhi/apps/web`，使用 Vue 3 + Vite。
- 后端与异步任务：`xingzhi/apps/server`，使用 Fastify + PostgreSQL；Server 处理接口，Worker 处理支付、退款等异步任务。
- 共享契约：`xingzhi/packages/contracts`，保存前后端共用的请求、响应和 UI 类型。

默认本地地址：

| 服务 | 地址或目录 |
| --- | --- |
| 消费者 H5 | `http://localhost:5173` |
| 商户/审核工作台 | `http://localhost:5174` |
| 后端 API | `http://localhost:8877` |
| 微信小程序产物 | `xingzhi/apps/miniapp/dist/weapp` |

### 3.2 执行顺序与范围

顺序固定为 **D1 跨角色后端 → D2 页面联调与 Simulation → D3 设备与 Sandbox 演示**。D 编号表示本次续开发顺序，不重算历史 A/B 或 M1/M2 完成率。先完成一个大阶段的小任务，再做该阶段一次集中验收；未通过先修复并只复测受影响范围。D1 通过前不修改管理端或消费者业务页面。

目标是让现有消费者链与商户处理、审核证据使用同一订单事实。保持 Simulation 为日常环境；银行真实接入、生产部署和大规模商户平台不作为当前竞赛 Demo 的前置条件。**D1、D2 已于 2026-09-22 完成开发和各自的集中验收；D3.1 代码准备、D3.2 包体评估、D3.3 Sandbox 代码收口和 D3.4 演示材料准备均已完成。当前不把这些代码或材料的完成等同于外部验收通过；剩余是微信开发者工具主线、至少一台真机主线、全新支付宝 Sandbox 同单连续链、商户处理与审核证据现场核对，以及按脚本正式录制。**

| 身份 | 方法与路径 | 用途与主要边界 |
| --- | --- | --- |
| 商户 | `GET /api/merchant/consumer-orders`、`GET /api/merchant/consumer-orders/:id` | 读取本人商品的新订单列表与详情；详情聚合原确认、付款、取消、退款、操作和时间线 |
| 商户 | `GET /api/merchant/consumer-cancellations`、`POST /api/merchant/consumer-cancellations/:id/decisions` | 读取并批准或拒绝本人订单的人工取消申请；写入需要可信来源和 `Idempotency-Key` |

| 审核者 | `POST /api/reviewer/budget-periods/:id/evidence-exports`、`GET /api/reviewer/evidence-exports/:id` | 生成并下载 24 小时有效的 JSON/HTML 证据；生成、下载均重查审核范围，且下载限原申请人 |

D1 必须遵守的实现决定：

- **商户归属：** 不能把 provider=simulation/alipay 当成商户，也不能因角色是 merchant_admin 就读取全部新订单。先复用可核验的订单→意图→报价→商品归属；若现有商品归属可改变，则在建单时保存最小不可变商户归属关系。D1.1 必须锁定其中实际采用的方式再实现读取，避免后续换商户导致历史订单串权。历史新订单只在归属证据唯一且可核实时补关联，无法核实的保留“归属待核对”，不猜测回填；不为兼容旧接口填假 plan_id，也不放宽既有交易形状约束。
- **商户权限：** 商户只看本人商品订单及售后所需脱敏信息，不开放消费者账户余额、完整流水或其他预算项目。处理不得改变消费者已确认的费用上限、退款范围或原付款号；变化需重新取得相应确认，不能由商户直接写到账金额。对于按 provider 归属的任务，不能仅凭 provider 把全部任务交给某个商户。
- **审核权限：** 新增最小的 reviewer→budget_period 显式分配，测试分配由受控场景初始化；不建立通用权限后台。列表、详情、导出生成和下载均重查范围，不能因知道订单/导出 ID 越权。原计划分配继续用于原计划，不扩大为全用户账户访问。
- **证据：** 至少有业务编号、环境/来源、金额、原确认及依据版本、付款/退款状态、发生时间、执行主体、原操作和重试关联；关键字段来自持久事实，未知时说明缺失，不伪造历史版本。幂等关联提供记录标识即可，原始键和原始请求体不无差别导出；禁止输出凭据、完整账户号及模型私有推理。先复用现有 JSON/HTML 导出，不新增 PDF 或报表平台。
- **契约和迁移：** 修改涉及的状态与 DTO 统一放入 `packages/contracts`，保留明确的新旧范围区分；只整理本阶段实际消费的类型，不全仓抽象。迁移只追加当前最大编号之后的文件，实施时再确认编号，禁止改写 001—032 或清除历史事实。计划中新接口在实现后补录方法、路径、请求、响应及错误边界，再交前端消费。

**D1 集中验收出口：** 一次通过消费者 HTTP 购买/付款、同单取消申请、商户处理、Worker 退款、审核读取/导出的链；覆盖另一商户/未分配审核者拒绝、重复批准和退款不重发、未知结果保留、撤回后原单善后、新旧订单各一条读取。复用现有测试入口，补最少新跨角色回归并做服务端/契约类型检查，不运行前端构建。首次需要真实启动验证时只启动所需服务。结果登记第 6.7 节；全量历史套件只在影响范围确实广泛时执行一次。

## 4. 第一次启动

### 4.1 环境要求

- macOS（zsh）或 Windows PowerShell
- Node.js 22
- pnpm 11
- PostgreSQL（默认端口 5432）
- 微信开发者工具（仅开发小程序时需要）

### 4.2 准备配置

macOS（zsh）在仓库根目录执行：

```zsh
cp xingzhi/.env.example xingzhi/.env
```

Windows PowerShell 在仓库根目录执行：

```powershell
Copy-Item .\xingzhi\.env.example .\xingzhi\.env
```

然后编辑 `xingzhi/.env`，至少确认：

```dotenv
DATABASE_URL=postgresql://localhost:5432/xingzhi_dev
PORT=8877
WEB_ORIGIN=http://localhost:5173
SEED_DEMO_PASSWORD=请改成只在本机使用的测试密码
PAYMENT_MODE=simulation
```

如果本机 PostgreSQL 要求用户名和密码，请按本机实际连接方式补充 `DATABASE_URL`。不要提交 `.env`，不要把数据库密码、测试密码或支付密钥写入代码、截图和聊天记录。

### 4.3 一键启动

确认 PostgreSQL 已启动后，在根目录执行：

macOS（zsh）：

```zsh
./start-xingzhi.zsh --restart
```

Windows PowerShell：

```powershell
.\start-xingzhi.ps1 -Restart
```

首次在一个全新的隔离测试数据库准备账号时，才执行：

macOS（zsh）：

```zsh
./start-xingzhi.zsh --restart --seed
```

Windows PowerShell：

```powershell
.\start-xingzhi.ps1 -Restart -Seed
```

日常启动不要加 PowerShell 的 `-Seed` 或 zsh 的 `--seed`。现有资金账户、预算和订单受保护，种子脚本拒绝覆盖或重新激活时属于预期保护，不应通过删除业务数据绕过。

可选参数：

| 参数 | 用途 |
| --- | --- |
| PowerShell `-Restart` / zsh `--restart` | 停止本仓库旧开发进程后重启 |
| PowerShell `-NoBrowser` / zsh `--no-browser` | 启动成功后不自动打开浏览器 |
| PowerShell `-BackendOnly` / zsh `--backend-only` | 只迁移并启动后端 Server |
| PowerShell `-Seed` / zsh `--seed` | 仅对全新隔离测试库初始化演示账号和资金样例 |

启动窗口需要保持打开，按 `Ctrl+C` 停止本次全部服务。

## 6. 手动测试流程

### 6.1 启动冒烟

1. macOS 执行 `./start-xingzhi.zsh --restart --no-browser`；Windows PowerShell 执行 `.\start-xingzhi.ps1 -Restart -NoBrowser`。
2. 打开 `http://localhost:8877/api/health`，确认服务与数据库健康。
3. 打开消费者端 `http://localhost:5173` 和管理端 `http://localhost:5174`，确认不是白屏且控制台无持续报错。
4. 分别登录消费者、商户和审核者账号；确认角色进入自己的页面，不能越权读取其他角色数据。

### 6.2 消费者完整 Simulation 链

建议使用新隔离场景，按以下顺序测试并保存每一步的业务编号：

1. 登录，确认账户归属、授权状态和资金快照时间。
2. 检查资产流水与预算事实分开显示，未来收入、退款承诺和信用额度不得计入当前现金。
3. 建立或打开本月预算周期。基准示例为：已确认可用现金 2000 元（不是未来预计收入）、必要支出 900 元、储蓄目标 500 元、可调支出 400 元，可支配金额应为 200 元。
4. 在未绑定有效资金账户的情况下创建需求草稿，确认系统允许保存草稿但不伪造可下单状态。
5. 采纳需求草稿，进入候选商品比较；检查排序理由、来源、价格与有效期。
6. 用 99 元正式报价替换预算中的 80 元估算，确认可支配金额变为 181 元，而不是重复扣除 80+99 元。
7. 创建购买意图并查看确认页；金额、商品、报价版本、预算版本和确认范围必须清晰。
8. 连续点击两次确认，确认只产生一笔有效订单/支付动作。
9. 完成 Simulation 支付；刷新页面、退出重登后，订单状态仍可通过业务编号恢复。
10. 新增 400 元必要支出，确认原 181 元余量变为 219 元缺口，并出现计划影响说明。
11. 用户明确确认调整方案后再执行；Agent 不得静默修改生效预算或订单。
12. 进入订单与售后页，提交退款并等待 Worker 处理；区分“退款已受理/渠道成功”和“现金已到账”。
13. 刷新、重登并检查退款状态、订单时间线和证据仍可恢复。
14. 撤回账户授权后，确认历史订单和售后证据仍可查看，但不能继续读取或伪造新资金事实。

### 6.3 异常与权限

至少验证：

- 错误密码、过期会话、未登录访问和登录后切换角色路由。
- 消费者 A 不能读取消费者 B 的账户、预算、订单和草稿。
- 商户不能修改消费者预算；审核者只能读取允许的审计数据。
- 断开后端、暂停 Worker、弱网、超时后重试、重复提交、刷新和重新登录。
- 报价过期、预算版本变化、账户撤回时，旧确认不能继续执行。

## 7. 开发时必须保持的业务规则

- 金额在数据库和接口中使用“分”，展示层再格式化为元；不要使用浮点数参与资金计算。
- 正式报价替换同一预算占位估算，只计算差额，不能重复扣款。
- 未来收入、退款承诺、优惠额度和信用额度不能计为当前可用现金。
- 所有会产生副作用的接口必须保留幂等语义；恢复依赖业务编号和服务端事实，不依赖某个页面是否还开着。
- 确认购买时必须校验用户、报价、预算和授权版本；版本变化后要求重新确认。
- “退款渠道成功”不等于“银行卡现金已到账”，页面与审核证据必须分层表达。
- Agent 只能提出草稿或建议；调整预算、下单、支付、退款等动作需要用户明确确认。
- 撤回资金授权不删除历史订单、售后和审计证据，但必须阻止后续读取新的受保护资金事实。
- 新接口先定义或复用 `packages/contracts` 契约，再同步后端和两个前端，避免三处手写不同类型。

## 9. 常见问题

### 网页密码框闪烁或反复回登录页

先看浏览器网络面板中的第一条 `/api/session` 或 `/api/auth/login` 错误。通常是后端未启动、会话 Cookie 不可用、前后端端口不匹配，或数据库中的账号密码不是当前 `.env` 的密码。macOS 使用 `--restart`，Windows PowerShell 使用 `-Restart`，保证所有服务来自同一份代码和配置。

### 小程序提示“尚未配置可访问的 API 地址”

开发者工具本地构建由启动脚本注入 `http://127.0.0.1:8877`。真机必须改成手机可访问的 HTTPS 地址并配置微信合法域名；电脑本机地址不能直接给真机使用。

### 小程序白屏

依次检查：启动窗口中的微信编译错误、`dist/weapp/app.json` 是否存在、开发者工具导入目录是否为 `apps/miniapp`、缓存是否仍指向旧产物、请求是否因 401/网络错误中断。不要用旧 H5 目录作为小程序目录。

### 端口被占用

macOS 执行 `./start-xingzhi.zsh --restart`；Windows PowerShell 执行 `.\start-xingzhi.ps1 -Restart`。如果仍失败，查看报错中的具体端口，关闭占用 5173、5174 或 8877 的非行止进程后重试。

### 种子初始化报账户缺失、归属不符或已撤回

这是数据保护，不是普通启动失败。不要对正在使用的数据库反复 Seed；创建新的隔离数据库或使用 `db:seed:consumer-scenario` 建立新的唯一测试场景。
