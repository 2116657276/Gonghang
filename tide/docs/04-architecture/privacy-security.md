## 1. 数据边界

原型只允许固定模拟数据或获得同意后的完全脱敏结论。禁止收集或保存企业名称、统一社会信用代码、账户、身份证件、联系方式、合同号、客户名、精确地址、精确金额、原始合同、银行流水、征信信息、访谈录音和内部银行规则。

案例以匿名标识、相对关系、日期区间、比例范围和角色类别表达。若多个单独脱敏字段组合后可能重新识别，必须进一步泛化或删除。

## 3. 授权最小化

授权记录用途、字段范围、接收角色、授予时间、到期时间和状态。导出时必须实时校验，不能依赖按钮是否曾启用。撤回后立即禁止新导出；既有审计事实可按最小合规需要保留，但不能继续传播摘要内容。

## 4. 脱敏与日志

- `sourceExcerpt` 只保留支持候选或核验所需的最短片段，进入日志前全部移除。
- 前端默认遮蔽非必要字段，手机端不显示内部复核内容。
- 错误日志不含请求正文、证据摘录、授权内容、密钥、令牌或本机路径。
- 协同摘要采用字段白名单，不从案例对象直接序列化全部数据。
- 导出文件含“竞赛原型、模拟/脱敏信息、非授信结论”标识。

## 5. 规则与模型治理

确定性规则的版本、输入摘要和输出需要可追溯。材料提取器只生成候选，不能核验证据、切换状态或生成审批建议。未来引入模型适配器前必须另行完成数据来源、提示注入、输出验证、版本、评估、人工责任和退出机制审查。

## 6. 审计事件

需要审计的动作包括正式重算、证据创建与状态变化、候选接受/拒绝、任务状态变化、人工覆盖、授权授予/撤回/到期、导出成功/失败和种子重置。事件为追加式记录；修改或清理仅允许受控演示重置，不得制造业务效果。

## 7. 威胁与控制

| 风险 | 控制 |
| --- | --- |
| 脱敏不足导致再识别 | 字段白名单、案例模板、组合风险复核、不保存原件。 |
| 前端缓存绕过授权撤回 | 导出时服务端实时校验授权；禁用缓存导出结果。 |
| 候选被误当作已核验证据 | 类型隔离，接受后固定生成 `PENDING`，服务端禁止直接提交 `VERIFIED`。 |
| 人工覆盖抹除规则事实 | 原解释按版本追加，覆盖记录单独保存且理由必填。 |
| 沙盘污染正式状态 | 纯函数深拷贝、无写接口、显著假设标识。 |
| 模拟数据被误解为真实客户 | 页面、摘要、路演材料和种子均注明模拟/脱敏。 |

## 8. 明确禁止

原型不得输出授信、审批、续贷、处置、信用评分或违约概率；不得保证融资、回款或经营结果；不得宣称工行合作或真实接入；不得用公开行业材料冒充客户验证；不得以技术演示为由收集真实敏感数据。
