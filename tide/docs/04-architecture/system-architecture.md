# 潮汐·创证系统架构

> 文档状态：历史研究分支。本文架构面向科创双证据研究原型，不代表当前潮汐工程架构已确定。

## 一、状态说明

本文描述概念架构，用于说明模块边界、数据流和责任分工。仓库当前只保留文档，不包含可运行系统；路演不得把本架构表述为已上线能力或真实机构接入。

## 二、分层架构

| 层级 | 组件 | 职责 |
| --- | --- | --- |
| 交互层 | 项目总览、材料工作台、双证据地图、复核页、护照页 | 展示状态与接收用户操作 |
| 应用层 | 项目编排、材料处理、复核流程、导出服务 | 组织用例并校验权限 |
| 领域层 | 事实账本、双证据图、双时钟、状态机 | 执行确定性规则和不变量 |
| 提取层 | 文档解析、字段提取、来源定位 | 生成候选事实，不认定真实性 |
| 基础设施层 | 本地数据库、对象存储、日志、模拟适配器 | 持久化、审计和演示隔离 |

## 三、处理链路

`授权 → 文件隔离存储 → 离线解析 → 候选事实 → 一致性校验 → 人工复核 → 双时钟重算 → 脱敏护照`

大模型如被使用，仅参与非决定性的文本归类或字段候选生成；事实状态转换、时间规则、权限、导出范围和审计必须由确定性逻辑控制。

## 四、后续原型建设顺序

1. 先固化研发链、订单链、跨链关系和事实状态的数据字典。
2. 再建立双时钟、状态机和异常案例的可复核规则。
3. 使用完全模拟数据制作交互页面和异常演示。
4. 完成测试记录后，才能在参赛材料中写入对应效果数字。
