## 1. 背景

竞赛要求稳定演示、快速迭代和可解释规则。团队需要在桌面主演示与手机辅助验证之间共享类型，同时保持离线可重复，避免网络、密钥、外部接口和模型波动影响答辩。

## 2. 决策

采用 TypeScript Web 全栈：React + TypeScript + Vite 客户端、Node.js + Fastify 服务层、本地 SQLite、Vitest 与 Playwright。领域逻辑放在无框架依赖的共享包，先完成文档、契约、规则、种子和单元测试，再建设页面、服务和数据库。

0.2.0 已实现 `@tide/contracts`、`@tide/domain`、`@tide/extraction` 与种子案例。尚未实现的应用层能力不得在文档或路演中描述为已经上线。

## 3. 关键约束

- 状态计算为确定性纯函数；前端与控制器不得复制规则。
- 沙盘为非持久化纯函数；正式修改需要独立命令和人工确认。
- 离线提取器实现可插拔接口，但本阶段没有网络模型、密钥和生产配置。
- SQLite 只存模拟或完全脱敏数据；不设计真实银行生产连接器。
- 桌面端 1440×900 主演示，手机端 390×844 只实现企业行动、解释和授权。

## 4. 结果

优点是类型、规则与测试可共享，离线演示稳定，状态变化可重复，未来能替换界面或提取适配器而不改领域契约。代价是需要清晰区分领域对象、传输对象和持久化表，并由服务层处理事务、权限与审计。

## 5. 被拒绝的方案

| 方案 | 拒绝理由 |
| --- | --- |
| 先做静态页面再补规则 | 容易形成只可观看、不可验证的演示。 |
| 以远程大模型直接给出风险结论 | 输出不可重复，难以追溯，也越过人工终审边界。 |
| 直接连接真实业务系统 | 缺少正式授权、合规审查和安全条件，不适合竞赛原型。 |
| 同时开发多行业模板 | 稀释主链路，增加证据和演示成本。 |

## 6. 复审条件

获得正式生产接入授权、需要多用户并发、引入真实模型、需要跨设备部署或主案例行业确定时，新增 ADR 评估，不直接修改本记录。
