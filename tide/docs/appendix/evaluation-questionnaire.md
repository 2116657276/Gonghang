## 1. 使用说明

本问卷用于小规模原型可用性测试。参与者先观看或操作 CASE-DEMO-001 的主流程，再独立作答。结果仅用于修正界面、文案和任务逻辑，不用于宣称真实经营效果或正式用户研究结论。

测试前向参与者说明：案例为模拟或已脱敏材料，系统不代表真实银行系统，不提供融资或审批决策。

## 3. 理解度问题

请在不返回页面的情况下回答：

1. 当前案例为什么被标记为“双重承压”？
2. 哪一项证据变更后，案例状态发生了怎样的变化？
3. 当前仍然需要由谁完成什么任务？
4. 潮汐是否自动决定企业能否获得融资、续贷或资金？为什么？
5. 企业撤回授权后，客户经理还能否继续生成新的协同摘要？

每题记录正确、部分正确或不正确，并记录误解点。

## 4. 主观反馈

采用 1 至 5 分量表：

| 问题 | 评分 |
| --- | --- |
| 我能理解“回款时钟”和“风险缓冲时钟”的差异。 | 1–5 |
| 我能看懂系统为什么给出当前状态。 | 1–5 |
| 我能找到下一步要处理的任务。 | 1–5 |
| 我认为系统的边界说明足够清楚。 | 1–5 |
| 企业手机页面的信息量对我而言合适。 | 1–5 |

开放问题：

1. 哪个词、哪个状态或哪个页面最让你困惑？
2. 你最希望增加、删除或改写什么？
3. 你是否误以为系统会替银行审批？若有，哪处文案导致了这种理解？

## 5. 结果记录与使用限制

| 指标 | 计算方式 | 允许的表述 |
| --- | --- | --- |
| 状态理解率 | 正确回答第 1 题的人数 / 有效参与者人数。 | “在 N 名原型测试参与者中，M 名正确理解当前状态。” |
| 边界理解率 | 正确回答第 4、5 题的人数 / 有效参与者人数。 | “测试中发现/未发现对自动审批边界的误解。” |
| 任务可发现性 | 能独立找到行动清单的人数 / 有效参与者人数。 | “用于迭代界面，不代表真实业务效率。” |

不得将小样本问卷写成“客户满意度”“系统降低风险”“提升授信通过率”或任何可泛化的经营成效。
