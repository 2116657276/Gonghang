## 1. 访谈目标

访谈用于验证潮汐的业务语言、时间节点、人工任务和边界是否合理，不用于获取真实客户资料、内部审批规则、系统权限、风控阈值或商业秘密。

优先覆盖两类角色：

1. 小微企业经营、客户服务或业务经办相关角色。
2. 风控、合规、资料审核或处置准备相关角色。

## 2. 开场知情同意口径

可使用以下说明：

“我们正在制作一个用于大学生金融科技竞赛的本地演示原型，研究小微企业经营周转中回款与风险缓冲材料的时间错配。访谈只记录匿名结论，不收集姓名、企业名称、账户、合同、客户资料、内部规则或任何保密信息。你可以跳过任何问题，也可以决定你的观点是否允许被匿名引用。该原型不会连接真实银行系统，也不会据此作出融资或风险决策。”

记录受访者选择：仅内部设计、允许匿名竞赛引用、不同意记录。

## 3. 通用问题

1. 在短期经营周转中，哪些时间点最容易让企业或服务人员被动？
2. 回款预计日、实际可用日和资料核验完成日之间通常有哪些差异？
3. 现有沟通中，哪些信息最分散或最难说明？
4. 当出现压力时，第一步通常由谁做什么？哪些动作必须由人工判断？
5. 什么样的风险提示会被认为“有用且不误导”？什么样的提示会造成误解？
6. 若只展示脱敏时间线、证据状态和待办，哪些字段最有帮助，哪些字段不应出现？

## 4. 角色补充问题

### 4.1 面向经营/业务端

- 企业最难理解的是回款、材料、费用、期限还是沟通责任？
- 企业是否愿意查看“回款承压/缓冲承压”这样的解释？哪些词更容易理解？
- 企业希望在手机上看到哪些三项以内的行动？
- 对共享结构化摘要，企业最关心字段范围、接收对象还是撤回权？

### 4.2 面向风控/合规端

- 回款与风险缓冲分开表达是否有助于拆解处理任务？
- 哪些证据可以作为“已核验”的最低条件，哪些必须维持待核验？
- 哪些状态必须保留人工终审，不能由系统自动推进？
- “警戒线”如何表述才能避免被理解为自动违约判断？

## 5. 记录模板

| 字段 | 记录方式 |
| --- | --- |
| interviewId | INT-YYYY-XXX，仅匿名编号。 |
| 角色类别 | 企业经营/业务、客户服务、风控合规等。 |
| 日期 | 访谈日期。 |
| 可引用范围 | 内部、匿名竞赛引用或不可记录。 |
| 关键结论 | 用受访者认可的匿名摘要记录。 |
| 支撑的文档/规则 | 例如双时钟定义、任务优先级、企业文案。 |
| 限制 | 单一角色观点、未核验、样本不足等。 |

## 6. 禁止询问或保存

不得要求或保存客户姓名、企业名称、账户、身份信息、详细地址、合同原件、完整流水、内部审批规则、系统账号、接口密钥、未公开风控参数或任何可回溯真实业务的截图。
