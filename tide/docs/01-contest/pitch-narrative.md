## 1. 核心主张

评委在前 30 秒应听懂：小微企业的周转问题不只是“有没有钱”，还包括“关键回款依据走到哪一步、备用安排何时才具备确认条件”。潮汐不替银行判断该不该贷，而是把时间来源、证据缺口和责任动作变成可解释闭环。

## 2. 时间分配

| 时间 | 叙事 | 屏幕或材料 | 必须说清 |
| --- | --- | --- | --- |
| 0:00–0:40 | 供应链小微的时间错配 | 一张订单—验收—结算时间线 | 有订单不等于回款已可用。 |
| 0:40–1:30 | 回款三证链缺口 | 证据护照 | 日期来自交易承诺、履约验收、结算可用。 |
| 1:30–2:30 | 双时钟解释 | 警戒线与两个日期区间 | 状态按日期规则，证据影响可计算性和置信度。 |
| 2:30–4:20 | 初始案例 | `DUAL_PRESSURE + LOW` 解释卡 | 不输出信用分或审批意见。 |
| 4:20–5:30 | 假设情景沙盘 | 前后差异视图 | 模拟不写入正式案例。 |
| 5:30–6:20 | 人工复核 | 任务、原规则结果和复核理由 | 人工覆盖不抹除历史计算。 |
| 6:20–7:10 | 企业授权摘要 | 手机授权与桌面导出 | 撤回后立即禁止导出。 |
| 7:10–8:00 | 差异化与证据边界 | 对比卡、调研状态 | 方向有公开依据，业务效果仍待验证。 |

## 3. 固定演示动作

1. 打开 `CASE-DEMO-001`，展示参考日、业务警戒线、主回款区间和主周转保障区间。
2. 展示回款三证链：交易承诺已核验，履约验收与结算可用待核验；解释初始 `DUAL_PRESSURE + LOW`。
3. 进入沙盘，把履约与结算候选设为已核验，并将主回款区间调整为 2026-09-26 至 2026-09-29。
4. 对比显示 `SAFEGUARD_PRESSURE + MEDIUM`，点明“回款压力缓解，但周转保障仍承压”。
5. 进入人工复核，展示规则结果、原因、任务依据和人工理由并存。
6. 由企业侧授权导出最小化协同摘要；随后撤回授权，再次导出必须失败并留下审计事件。

## 4. 差异化答问

| 评委问题 | 建议回答 |
| --- | --- |
| 与 CRM 有何不同？ | CRM 管联系和跟进；潮汐管日期依据、证据阶段、警戒线、规则解释与复核闭环。 |
| 是否在做信用评分？ | 不是。状态只描述日期区间关系，置信等级只描述证据质量。 |
| 是否是智能尽调？ | 提取器只提出候选，接受后仍待核验；任何正式结论都依赖人工核验和确定性规则。 |
| 为什么需要两个时钟？ | 回款可能提前但备用安排仍未就绪，单一预警会把局部改善误写为风险消失。 |
| 是否已接入工行？ | 没有。当前完全离线，公开材料只用于证明方向相关性。 |
| 有真实效果吗？ | 当前尚未形成足够样本，效率和可用性是原型假设，将按两类角色、两案例和专业反馈验证。 |

## 5. 禁用表达

不得说“替银行审批”“预测能否贷款”“已经接入工行数据”“模型准确率”“保证企业获得融资”“风险已经解决”。推荐使用“规则状态”“证据准备度”“人工复核”“假设情景”“原型假设”和“公开方向依据”。

## 6. 退化演示方案

若现场时间不足，只演示一条链路：初始双重承压 → 沙盘核验回款链 → 周转保障承压 → 企业授权摘要 → 撤回后导出失败。若页面尚未完成，使用种子 JSON、规则测试结果和静态交互稿，不宣称未实现能力。
