# 潮汐·创证路演叙事

> 文档状态：历史研究分支。本文的科创定位和双证据表述尚未迁移到当前小微借贷周期方向。

## 一句话定位

潮汐·创证把科创小微企业“研发做到哪、订单兑现到哪、材料准备到哪”变成两条可追溯证据链和两个可解释时间窗口。

## 六段式叙事

### 1. 看见时间错位

一家小型科技企业可能已经完成试制并拿到订单，却因为研发投入前置、验收回款后置、证明材料分散，在真正需要资金时只能提交一份尚未反映变化的历史报表。

### 2. 看见真正缺口

问题不是“没有数据”，而是研发、产品、订单、交付与结算之间缺少可验证的连接。合同不能自动证明履约，专利也不能自动证明产品化。

### 3. 给出双证据结构

潮汐分别建立研发里程碑链和订单兑现链。每个节点都能追溯到材料位置，并明确它是候选事实、存在冲突、待人工复核还是已核验。

### 4. 给出双时钟解释

资金时钟展示订单资金可能何时可用；就绪时钟展示关键证据包何时具备人工受理条件。两个时钟与企业保护日比较，提示的是窗口压力，而不是审批预测。

### 5. 用异常证明可信

演示重点不是“系统识别了多少材料”，而是它发现产品版本冲突、缺少验收单时没有自动修复或给出高分，而是定位来源、暂停结论并转入人工复核。

### 6. 收束银行价值

潮汐不替银行做决策。它帮助企业更有序地准备材料，帮助客户经理更快看见证据来源、断点和时间关系，让科技金融服务从“收一摞材料”前移到“理解一段可核验的经营进程”。

## 建议演示节奏

| 时间 | 展示 | 必须说清的边界 |
| --- | --- | --- |
| 0:00—0:40 | 企业背景与保护日 | 全部数据为模拟数据 |
| 0:40—1:40 | 双证据链自动整理 | 机器抽取只形成候选事实 |
| 1:40—2:40 | 版本冲突与验收缺口 | 冲突不自动消失，需人工复核 |
| 2:40—3:30 | 双时钟与缺口待办 | 不预测审批和到账结果 |
| 3:30—4:20 | 脱敏证据护照 | 不替代银行尽调与授信审批 |
| 4:20—5:00 | 用户价值与验证计划 | 不使用无测试依据的效果数字 |

## 答辩禁区

- 不说“凭订单和专利就能贷款”。
- 不说“AI 判断企业技术先进性”。
- 不说“系统生成银行认可的信用分”。
- 不说“保证在保护日前到账”。
- 不用模拟材料推导真实行业转化率或授信提升率。
