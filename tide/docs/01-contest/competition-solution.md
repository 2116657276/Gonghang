# 潮汐·创证竞赛方案

> 文档状态：历史研究分支。本文仍以科创小微企业和双证据链为对象，仅供研究参考，不代表当前潮汐实施方向。

## 一、项目摘要

潮汐·创证是一项面向科创小微企业的双证据融资协同服务。项目针对“研发投入已经发生、产品正在验证、订单开始形成，但财务报表尚未完整反映经营进展”的时间错位，将研发立项、技术验证、检测认证、知识产权、试制记录与订单、交付、验收、结算材料组织为两条可追溯证据链，帮助企业和银行客户经理更早发现材料缺口、解释冲突并对齐融资准备窗口。

系统不判断技术先进性，不直接给出授信额度或审批结果。它的职责是把散落、异构且时序复杂的材料转换为可查看来源、可追踪状态、可进入人工复核的证据护照。

## 二、问题界定

科创小微企业经常同时遭遇三种错位：研发投入先于收入形成，订单履约先于回款可用，企业内部材料准备晚于资金需求。传统财务指标能够说明历史结果，却难以及时描述“技术走到了哪里、产品对应哪笔需求、订单能否完成交付、资金何时可能可用”。

这不是单纯的材料上传问题。若研发成果与产品不匹配、订单主体与交付主体不一致、验收时间早于交付时间，材料越多反而越难形成可信叙事。因此项目将“证据之间的关系和时间”作为核心对象。

## 三、解决方案

### 3.1 两条证据链

| 证据链 | 典型节点 | 回答的问题 |
| --- | --- | --- |
| 研发里程碑链 | 立项 → 技术验证 → 检测/认证 → 试制 → 知识产权 → 产品映射 | 技术活动是否连续推进，是否与目标产品存在可解释关系 |
| 订单兑现链 | 订单承诺 → 交付 → 验收 → 结算 → 资金可用 | 市场需求是否存在，履约与回款是否有可追踪依据 |

两条链不强行合并为一个“信用分”。系统只标记连接关系，例如某项检测对应哪个产品版本、某批交付对应哪张订单、某笔结算对应哪项验收，并展示来源和置信边界。

### 3.2 双时钟

| 时钟 | 计算对象 | 输出方式 |
| --- | --- | --- |
| 资金时钟 | 订单履约、结算条件和资金预计可用区间 | 最早/基准/最晚区间及依据 |
| 就绪时钟 | 关键证据缺口补齐、冲突复核和材料包形成 | 待办节点、责任人、目标日期 |

双时钟与企业授权录入的工资、税费或关键采购“保护日”比较，只用于识别时间窗口压力，不预测审批结果。

### 3.3 证据护照

每个事实保留材料来源、页码或字段定位、抽取方式、规则校验结果、人工复核状态、版本和访问权限。机器识别结果默认属于候选事实，只有通过核验后才进入已核验区。

## 四、目标用户与价值

| 用户 | 主要困难 | 潮汐输出 |
| --- | --- | --- |
| 科创小微企业负责人/财务 | 不知道材料是否足以解释研发与订单进展 | 双证据地图、缺口清单、时间窗口 |
| 研发或项目负责人 | 技术材料与商业订单缺少映射 | 里程碑节点、产品版本关系、冲突提示 |
| 银行客户经理 | 材料来源分散，前期核对成本高 | 可追溯证据包、异常项、人工复核记录 |
| 园区/孵化器服务人员 | 难以分层组织企业融资准备服务 | 经授权的材料就绪状态与辅导待办 |

## 五、演示闭环

原型使用虚构企业“澄芯微控”及模拟数据。企业拥有传感器研发记录、检测报告、软件著作权、试制批次和两笔客户订单，但存在一项产品版本不一致及一张验收单缺失。

1. 上传材料后，系统形成候选研发链和订单链。
2. 规则引擎发现检测报告对应 V2.1，而订单附件仍写 V2.0，标记版本冲突；另一订单缺少验收材料，标记证据缺口。
3. 用户查看来源定位并提交说明，客户经理在人工复核页记录结论。
4. 双时钟显示：订单资金预计在保护日之后可用，而材料包可在保护日前完成复核，形成“先补证据、再进入人工评估”的清晰窗口。
5. 导出脱敏证据护照，明确已核验项、待核验项、冲突和未提供材料。

Demo 不连接真实银行、征信、支付或企业生产系统，不展示虚构授信额度、放款结果或业务提升比例。

## 六、创新点

1. **从结果指标转向过程证据。** 用研发推进和订单兑现补充财务报表的时间滞后，但不否定传统风控指标。
2. **双链交叉而不黑箱合分。** 研发与商业证据分别呈现，可理解、可追溯、可人工修正。
3. **把材料准备纳入时间管理。** 就绪时钟与资金时钟共同暴露“钱何时来、材料何时齐”的错位。
4. **证据状态分层。** 明确候选、冲突、待复核和已核验，避免把模型识别包装成事实认证。

## 七、边界与验证

本项目不替代银行审批，不承诺授信，不评价专利价值，不将订单金额直接等同于可还款能力，也不默认采集企业全量经营数据。初赛应验证字段抽取准确性、一致性规则有效性、用户对缺口和状态的理解度、证据来源可追溯性及异常场景能否正确转人工。
