# 潮汐·创证证据护照规范

> 文档状态：历史研究分支。本文护照结构适用于科创双证据研究，当前项目是否采用需重新评审。

## 一、用途

证据护照用于在企业授权范围内，向企业、银行客户经理或园区服务人员清晰展示双证据链、事实来源、核验状态、未解决问题和时间窗口。它是材料组织与协同载体，不是信用证书、技术鉴定或授信意见。

## 二、固定结构

| 分区 | 必备内容 |
| --- | --- |
| 基本信息 | 匿名主体、项目、产品版本、生成时间、护照版本 |
| 研发里程碑 | 节点、日期区间、来源、状态、产品映射 |
| 订单兑现 | 订单、交付、验收、结算、资金状态及来源 |
| 跨链映射 | 研发成果与产品/订单关系、依据与核验状态 |
| 双时钟 | 资金区间、就绪区间、保护日、计算依据 |
| 异常与缺口 | 冲突、缺失、过期、责任人和下一步 |
| 复核记录 | 复核人角色、时间、意见、前后版本 |
| 权限与声明 | 接收方、用途、有效期、脱敏规则和边界声明 |

## 三、状态展示

已核验、待人工复核、存在冲突、证据缺口和已过期必须分区或使用同时包含颜色、文字和图标的标识，不能只靠颜色。模型提取置信度不得与事实核验状态并列为“可信度分数”。

## 四、导出规则

1. 默认隐藏企业证件号、账户号、联系人、完整订单号和商业秘密附件全文。
2. 仅导出支持当前用途的最小字段，接收方不能沿用过期链接访问新增材料。
3. 护照生成后形成不可静默修改的快照；更新内容必须生成新版本。
4. 未解决事项必须随护照导出，不得为了版面完整而省略。
5. 每页或首页显著位置写明“材料协同用途，不构成授信意见”。

## 五、最小验收样例

一份合格的原型护照至少包含三项研发节点、两项订单节点、一项跨链映射、一项冲突、一项缺口、两个时间区间及一次人工复核记录，并能从每个事实返回模拟来源位置。
