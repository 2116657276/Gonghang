# 潮汐·创证双时钟规则

> 文档状态：历史研究分支。本文“双时钟”只表达科创双证据方案的设计规则，当前项目不自动继承。

## 一、设计原则

双时钟用于解释“订单相关资金何时可能可用”和“关键证据包何时可能就绪”。二者均为带依据的时间区间，不是承诺日期，也不用于直接预测贷款审批。

## 二、资金时钟

### 2.1 输入

订单金额、交付状态、验收条件、结算方式、账期、历史回执或人工确认信息。只有订单金额而无履约和结算依据时，不计算确定区间。

### 2.2 输出

`earliestDate`、`baselineDate`、`latestDate`、`basisRefs`、`confidenceLevel` 和 `unresolvedConditions`。置信等级只描述日期依据完整度，不描述客户信用质量。

### 2.3 规则示例

| 条件 | 处理 |
| --- | --- |
| 已验收且结算条款明确 | 以验收日和条款计算基准区间 |
| 已交付但未验收 | 将验收作为未解决条件，扩大最晚日期 |
| 仅有订单承诺 | 显示“无法估计资金可用日” |
| 多笔订单 | 分笔计算后展示分布，不简单取总金额加权平均 |

## 三、就绪时钟

### 3.1 输入

关键研发节点完整度、订单节点完整度、冲突数量、补充材料目标日期、复核人响应时间和共享授权状态。

### 3.2 输出

`readyEarliestDate`、`readyBaselineDate`、`readyLatestDate`、`blockingGaps`、`owners` 和 `reviewBasis`。

### 3.3 规则示例

| 条件 | 处理 |
| --- | --- |
| 关键节点完整且无冲突 | 根据复核队列估计就绪区间 |
| 缺材料但有责任人和目标日 | 将目标日纳入基准与最晚日期 |
| 存在无责任人的关键冲突 | 状态设为“无法估计”，要求分配责任人 |
| 共享授权已过期 | 暂停就绪计算，提示更新授权 |

## 四、与保护日比较

| 状态 | 严格含义 | 界面提示 |
| --- | --- | --- |
| `STEADY` | 两个基准日期均不晚于保护日 | 当前窗口未发现明显时间挤压 |
| `CASH_PRESSURE` | 资金基准日期晚于保护日 | 订单资金窗口可能晚于经营约束日 |
| `READINESS_PRESSURE` | 就绪基准日期晚于保护日 | 关键材料可能无法在保护日前就绪 |
| `DUAL_PRESSURE` | 两个基准日期均晚于保护日 | 资金与材料窗口同时承压 |
| `PENDING_VERIFICATION` | 任一时钟缺少关键依据 | 先补充或复核依据，不输出确定判断 |

当区间跨越保护日时，界面应展示“不确定区间跨越保护日”，不得仅依据基准日期显示绿色安全状态。

## 五、重算与审计

每次订单状态、材料状态、保护日或复核结论变化都触发重算，并记录输入版本、规则版本、旧结果、新结果与触发人。任何人工覆盖必须填写理由，且不能删除原计算记录。
