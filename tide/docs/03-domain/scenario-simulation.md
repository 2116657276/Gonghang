## 1. 定义

双时钟沙盘通过纯函数 `simulateRiskCase(snapshot, patch)` 比较正式快照与假设情景。它用于解释“如果某项日期或证据状态变化，会发生什么”，不是预测器、审批工具或正式修改入口。

## 2. 允许的临时修改

| 字段 | 含义 | 验证 |
| --- | --- | --- |
| `guardDate` | 假设业务警戒线。 | 合法且不早于参考日。 |
| `cashflowDateRange` | 唯一主回款区间。 | 起止合法且有唯一主节点。 |
| `safeguardDateRange` | 唯一主周转保障区间。 | 起止合法且有唯一主节点。 |
| `evidenceChanges[]` | 指定运行时证据的临时状态。 | 证据必须存在，状态来自正式证据枚举。 |

沙盘不允许修改案例身份、行业、来源类型、证据摘录、可见角色、人工覆盖、授权或审计事件。

## 3. 返回值

成功结果同时包含 `baseline` 和 `projected` 完整解释，并返回 `statusChanged`、`confidenceChanged`、新增/移除原因、任务新增/移除。任务差异按类型、标题、角色和优先级比较；所有说明仍遵守正式规则的禁止动作。

非法日期补丁返回 `INVALID_SCENARIO_PATCH`，证据不存在返回 `EVIDENCE_NOT_FOUND`，正式或模拟计算本身的输入错误沿用领域错误码。

## 4. 非持久化语义

实现先对快照进行深拷贝，再把补丁应用到副本；不修改输入对象、种子 JSON、正式状态或审计记录。多个沙盘操作可以在界面临时累积，但刷新、关闭或重置时丢弃。未来页面必须持续显示“假设情景”和与正式快照的差异。

若用户希望正式采纳变化，必须新建独立命令：提交结构化变更 → 校验权限和授权 → 人工确认 → 写正式数据 → 重新调用 `calculateRisk` → 追加审计事件。不得把 `projected` 对象直接保存。

## 5. 主情景

| 项目 | 基线 | 假设情景 |
| --- | --- | --- |
| 回款区间 | 2026-10-13 至 2026-10-19 | 2026-09-26 至 2026-09-29 |
| 履约证据 | `PENDING` | `VERIFIED` |
| 结算证据 | `PENDING` | `VERIFIED` |
| 周转保障区间 | 2026-10-26 至 2026-11-30 | 不变 |
| 状态 | `DUAL_PRESSURE` | `SAFEGUARD_PRESSURE` |
| 置信等级 | `LOW` | `MEDIUM` |

解释差异必须明确：回款区间提前且回款三证链完整度提高；周转保障人工确认仍待完成且日期晚于警戒线，所以不能显示稳态或“已解决”。

## 6. 验收

- 调用前后输入对象深度相等。
- 相同快照和补丁得到完全相同结果。
- 非法区间和不存在的证据被拒绝。
- 返回状态、置信度、原因和任务差异。
- 不产生授权、覆盖和审计副作用。
