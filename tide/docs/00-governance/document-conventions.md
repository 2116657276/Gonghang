## 1. 适用范围

本规范适用于 `docs/` 下除 `archive/` 外的全部现行 Markdown。正式说明性材料只在 `docs/` 维护；代码内注释用于解释局部实现，不承担产品定义。历史归档只读，不回填新术语。

## 2. 文件与结构

- 正文使用简体中文，文件名使用稳定英文小写加连字符。
- 每份文档必须包含版本、状态、负责人、更新时间和关联文档。
- 标题从一级到三级顺序递进；跨文件引用使用相对链接；图示统一使用 Mermaid。
- 结构化案例使用[脱敏案例模板](../appendix/anonymized-case-template.md)，不得自由扩充可识别字段。
- 现行文档统一版本为 `0.2.0`。内容变更先更新决策日志，再同步契约、规则、测试和叙事。

## 3. 状态与术语

唯一风险状态为 `STEADY`、`CASH_PRESSURE`、`SAFEGUARD_PRESSURE`、`DUAL_PRESSURE`、`PENDING_VERIFICATION`。唯一证据状态为 `PENDING`、`VERIFIED`、`REJECTED`、`EXPIRED`。唯一准备度为 `MISSING`、`PARTIAL`、`COMPLETE`。

中文术语必须从[术语表](glossary.md)选择。不得用相近表达替代“周转保障”“业务警戒线”“证据护照”“人工覆盖”“协同摘要”。英文类型和字段以 `packages/contracts` 为机器可读源。

## 4. 事实、假设和证据标注

| 标签 | 使用条件 | 可写内容 |
| --- | --- | --- |
| 已实现 | 有代码和自动化验证。 | “规则引擎已覆盖日期区间与证据失效保护。” |
| 已验证 | 有脱敏记录、同意口径和可追溯结论。 | “两类角色均确认某类缺口存在。” |
| 公开方向依据 | 有公开权威来源。 | “公开政策支持加强资金流信用信息共享。” |
| 原型假设 | 尚未完成访谈或样本验证。 | “预计可减少重复沟通，待调研验证。” |
| 不得表述 | 无证据或超出能力。 | 接入声明、准确率、审批能力、融资保证。 |

公开资料和访谈结论只能进入竞赛证据台账；运行时证据使用独立的来源枚举，不能把行业材料混入计算。

## 5. 变更与验收

重大变更包含定位、状态、实体、接口、权限、数据来源、Demo 主链路和合规边界。变更流程为：登记决策 → 更新术语与契约 → 更新领域和产品文档 → 更新架构与交付文档 → 增补测试 → 运行门禁。

文档合入前必须满足：内部链接有效、元信息为 0.2.0、现行术语无历史残留、没有真实接入或效果保证暗示、代码枚举与文档完全一致。
