# 潮汐·创证文档规范

> 文档状态：历史研究分支。本文约束科创双证据资料的写法；当前潮汐方向见[项目入口](../../README.md)，新的小微借贷周期方案确定后再建立现行规范。

## 一、状态与范围

本目录保留科创双证据研究文档，所有架构、接口、数据模型和页面均属于设计方案，不得表述为已经上线、真实接入或具备生产能力。

## 二、固定文档结构

方案类文档依次包含：定位、问题、用户、流程、输出、边界、验证。规则类文档依次包含：输入、状态、转换、异常、审计。表格必须使用统一列名和完整表头，不使用空行模拟段落。

## 三、证据等级

| 标记 | 含义 | 可用于 |
| --- | --- | --- |
| `[公开可核验]` | 可追溯到官方或权威公开来源 | 赛制、政策、行业背景 |
| `[访谈待核]` | 来自匿名访谈，尚未形成充分样本 | 用户问题假设 |
| `[原型假设]` | 为演示构造的企业、材料和日期 | Demo 与规则测试 |
| `[设计方案]` | 已在文档中定义、尚待原型验证 | 产品、规则与架构说明 |
| `[测试结果]` | 具有样本、方法、日期和可复核记录 | 原型验证结论 |

## 四、统一状态

事实状态使用 `CANDIDATE`、`CONFLICT`、`PENDING_REVIEW`、`VERIFIED`、`REJECTED`、`EXPIRED`；窗口状态使用 `PENDING_VERIFICATION`、`STEADY`、`CASH_PRESSURE`、`READINESS_PRESSURE`、`DUAL_PRESSURE`。中文解释以 [术语表](glossary.md) 为准。

## 五、合入检查

- 内部链接有效，标题层级连续，表格列数一致。
- 项目名称、副标题和状态与文档中心一致。
- 候选事实与已核验事实明确分开。
- 不出现无依据的准确率、效率、授信或市场规模结论。
- 不暗示真实银行接入、真实客户数据、自动审批或保证回款。
- 尚未经过原型测试的能力明确标注为设计方案。
