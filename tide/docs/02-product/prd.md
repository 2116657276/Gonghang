## 1. 产品定义

潮汐面向供应链小微企业经营周转，围绕业务警戒线组织回款三证链和周转保障链，输出双时钟规则状态、证据准备度、解释、核验任务、企业行动清单与授权协同摘要。产品治理的是时间、证据与协作，不判断信用好坏，不作授信和审批决定。

## 2. 用户问题

- 企业经营者知道“可能回款”，但难以说明日期由哪项订单、验收和结算依据支撑。
- 服务人员在多个材料和沟通记录之间重复核对，难以统一日期口径与责任人。
- 风险复核人员需要区分确定性规则、证据质量和人工判断，避免状态被无痕覆盖。
- 多方协作需要企业授权；一旦撤回，最小化摘要必须停止导出。

上述问题和价值尚待两类角色、两份脱敏案例和专业反馈验证；未验证部分均为原型假设。

## 3. 目标与非目标

### 3.1 目标

1. 在首屏解释主回款、主周转保障与业务警戒线的相对关系。
2. 为两条链展示证据阶段、状态、有效期、脱敏摘录和具体缺口。
3. 依据缺口生成去重任务，并保留任务依据和人工复核痕迹。
4. 允许非持久化假设情景比较，清楚显示前后变化。
5. 通过可撤回授权控制协同摘要导出。

### 3.2 非目标

- 不计算信用评分、违约概率、授信额度、融资通过率或业务收益。
- 不自动授信、审批、续贷、处置或替代人工复核。
- 不接入真实银行核心、征信、账户或第三方生产系统。
- 不把材料提取候选直接作为正式证据，不把任务完成等同于状态改善。

## 4. 输入、处理与输出

| 层次 | 范围 |
| --- | --- |
| 输入 | 脱敏回款节点、经营/合同节点、周转保障材料状态、证据核验状态、有效期、人工处理记录和授权状态。 |
| 处理 | 证据护照、双时钟日期规则、证据准备度、置信等级、四象限分类、沙盘比较、人工复核和审计。 |
| 输出 | 风险解释卡、证据缺口、核验任务、企业行动清单、经授权的协同摘要。 |

## 5. 功能需求

| 编号 | 需求 | 用户价值 | 领域依据 | 验收要点 |
| --- | --- | --- | --- | --- |
| FR-01 | 案例概览与双时钟 | 快速定位时间压力来源。 | 日期区间相对警戒线分类。 | 同屏显示两个区间、差值、状态和置信度。 |
| FR-02 | 证据护照 | 看清日期来源与缺口。 | 五个证据阶段、四种状态、三档准备度。 | 过期和拒绝证据不参与当前计算。 |
| FR-03 | 风险解释卡 | 解释状态为何产生。 | 规则原因、证据缺口和任务依据。 | 置信度旁必须说明“不是违约概率”。 |
| FR-04 | 核验任务台 | 把缺口转为动作。 | 按实际缺口生成并去重。 | 完成任务不自动改变案例状态。 |
| FR-05 | 双时钟沙盘 | 比较假设变化。 | `simulateRiskCase(snapshot, patch)`。 | 不修改正式对象；显示状态、置信度、原因和任务差异。 |
| FR-06 | 人工确认与覆盖 | 保留专业判断和责任。 | 规则状态与有效状态分离。 | 必填理由；保留原解释、时间差、操作者与时间。 |
| FR-07 | 企业行动清单 | 企业知道下一步做什么。 | 企业可见任务与脱敏证据。 | 手机端只显示最小信息，不暴露内部备注。 |
| FR-08 | 授权与协同摘要 | 控制跨角色共享。 | 有效授权、用途、范围、期限。 | 撤回后导出失败并留痕。 |
| FR-09 | 离线材料提取 | 降低模拟材料录入成本。 | 确定性提取候选。 | 候选接受后证据仍为 `PENDING`。 |
| FR-10 | 审计查看 | 支持追溯和答辩。 | 追加式事件记录。 | 计算、核验、覆盖、授权和导出事件可查询。 |

## 6. 规则和显示要求

- 有合法日期和每条链至少一条当前证据时，即使含 `PENDING`，仍可显示四象限，但置信度为低。
- 主节点不唯一、日期无效、区间跨警戒线、全部证据拒绝或过期时显示待核验。
- 低置信度表示关键阶段缺失、存在待核验证据或模拟估计；中置信度和高置信度按[领域规则](../03-domain/dual-clock-rules.md)执行。
- 沙盘使用醒目的“假设情景”标识；关闭或重置后回到正式快照。
- 人工覆盖不修改历史计算结果，状态卡同时显示规则状态和有效状态。

## 7. 桌面端与手机端职责

### 7.1 桌面端 1440×900

主演示包含案例概览、双时钟、证据护照、解释卡、任务台、沙盘、人工复核、授权摘要和审计记录。首屏建立“日期—证据—状态—动作”的因果关系，详细材料按需展开。

### 7.2 手机端 390×844

只提供企业行动清单、风险解释卡、授权确认与撤回。手机端不编辑规则参数、不执行人工覆盖、不查看内部复核备注，也不展示超出授权范围的证据摘录。

## 8. 异常与边界场景

| 场景 | 预期处理 |
| --- | --- |
| 主节点缺失或多于一个 | 待核验，指出“缺少唯一主节点”。 |
| 日期格式非法或起日晚于止日 | 拒绝输入或进入待核验，不计算中点。 |
| 覆盖比例不在 0–100 或下界大于上界 | 返回契约错误，不保存。 |
| 证据关联不存在 | 显示悬空引用缺口，生成相应核验任务。 |
| 证据过期或被拒绝 | 不参与当前支持和高置信度判断。 |
| 提取候选被接受 | 生成待核验证据，不触发状态变化。 |
| 授权已撤回 | 禁止导出，显示原因并写审计事件。 |
| 沙盘补丁非法 | 拒绝模拟，正式案例保持不变。 |

## 9. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 可解释性 | 每个状态、置信度和任务都有结构化依据。 |
| 可重复性 | 完全离线运行；相同输入产生相同输出。 |
| 隐私 | 种子与调研材料完全脱敏，默认最小可见，敏感字段不落日志。 |
| 安全 | 基于角色与授权的读取/导出控制，审计事件追加保存。 |
| 可用性 | 8 分钟路演可完成，4 分钟产品演示主链路不中断。 |
| 可访问性 | 键盘可达、焦点可见、状态不只靠颜色、关键文本符合对比度要求。 |
| 响应式 | 桌面主演示和手机三项企业能力在指定视口无横向溢出。 |

## 10. 成功标准

- 新成员能从文档中心在 10 分钟内定位契约、规则、Demo 和测试。
- 用户能在 60 秒内指出当前状态、首个证据缺口和责任动作。
- 主案例从 `DUAL_PRESSURE + LOW` 模拟为 `SAFEGUARD_PRESSURE + MEDIUM`，不得出现“已解决”。
- 沙盘不修改输入；人工覆盖保留原解释；授权撤回后导出必定失败。
- 所有活跃文档、契约、种子和测试使用相同字段、状态和术语。
