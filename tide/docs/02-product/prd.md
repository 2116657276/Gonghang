# 潮汐·创证产品需求文档

> 文档状态：历史研究分支。本文不作为当前小微借贷周期的 PRD；其中科创证据链内容仅供方法参考。

| 字段 | 内容 |
| --- | --- |
| 产品形态 | 双证据融资协同 Web 原型 |
| 原型边界 | 模拟数据、模拟接口，不连接真实金融或企业生产系统 |
| 当前状态 | 文档方案阶段，尚未建设生产系统 |

## 一、产品目标

在不替代银行审批的前提下，帮助科创小微企业将研发进程与订单兑现材料整理为可追溯、可解释、可人工复核的证据包，并清晰展示资金窗口与材料就绪窗口。

## 二、核心用户故事

1. 作为企业负责人，我希望知道现有材料能否连成研发与订单两条链，还缺什么。
2. 作为研发负责人，我希望看到检测、试制、知识产权与产品版本之间是否匹配。
3. 作为财务人员，我希望知道订单处于交付、验收、结算还是资金可用阶段。
4. 作为客户经理，我希望直接定位每项事实的来源、冲突和复核记录，而不是阅读无结构附件。
5. 作为复核人员，我希望保留修改理由、责任人和历史版本，避免机器结果被误当成最终事实。

## 三、功能范围

| 模块 | 必须具备 | 暂不纳入 |
| --- | --- | --- |
| 授权与材料空间 | 授权范围、材料分类、撤回共享、版本记录 | 全量企业数据接入 |
| 候选事实抽取 | 主体、产品、版本、订单、金额、日期、状态、来源定位 | 自动认定真实性 |
| 双证据图谱 | 研发链、订单链、跨链映射、断点和冲突 | 技术价值评分 |
| 双时钟 | 资金区间、就绪区间、保护日比较、依据说明 | 到账或审批概率预测 |
| 人工复核 | 接受、退回、补充说明、责任人、时间戳 | 自动代替银行审批 |
| 证据护照 | 脱敏导出、状态分层、来源与权限 | 对外公开企业敏感材料 |

## 四、关键规则

### 4.1 研发链最低结构

原型至少包含“研发立项或需求定义—技术验证或检测—试制/知识产权/产品映射”三类节点。缺少任一类并不代表项目虚假，只能形成对应缺口提示。

### 4.2 订单链最低结构

原型至少区分订单承诺、交付、验收、结算和资金可用五种状态。合同签署不自动等同于已交付，开票不自动等同于已回款。

### 4.3 一致性检查

系统检查主体、产品名称或版本、订单标识、金额、日期先后与状态来源。规则冲突时不得自动覆盖原始字段，必须展示双方来源并进入复核。

### 4.4 双时钟规则

资金和就绪均采用区间而非单点。缺少关键依据时显示“无法估计”，不得以默认日期伪装确定性。详见 [双时钟规则](../03-domain/dual-clock-rules.md)。

## 五、页面结构

| 页面 | 核心组件 | 主操作 |
| --- | --- | --- |
| 项目总览 | 双链摘要、双时钟、保护日、异常数量 | 查看证据断点 |
| 材料工作台 | 分类上传、来源定位、抽取状态 | 确认或纠正候选字段 |
| 双证据地图 | 节点、关系、版本、冲突 | 打开来源或提交说明 |
| 缺口与复核 | 缺失项、冲突项、责任人、目标日期 | 补充材料、接受或退回 |
| 证据护照 | 已核验/待核验分区、访问范围、导出记录 | 生成脱敏材料包 |

## 六、状态与权限

事实状态统一为 `CANDIDATE`、`CONFLICT`、`PENDING_REVIEW`、`VERIFIED`、`REJECTED`、`EXPIRED`。企业提交者可纠正候选字段但不能删除审计历史；复核者可改变核验状态但必须填写依据；查看者仅能访问授权范围内的脱敏内容。

## 七、非功能要求

- 每项事实必须可回到来源位置；来源失效时状态同步降级。
- 所有人工修改保留操作者、时间、前后值和理由。
- 敏感附件默认不公开导出；证据护照使用最小字段与脱敏标识。
- 同一文件重复上传和同一复核请求必须具备幂等处理。
- 原型页面必须持续显示“模拟数据，不构成授信意见”。

## 八、验收标准

1. 用户可从任一证据节点定位到模拟来源及页码/字段。
2. 至少正确演示一个版本冲突、一个缺失证据和一个时序异常。
3. 两个时钟均展示区间、依据和无法估计状态。
4. 候选事实不会被界面误写为已核验事实。
5. 导出护照包含来源、状态、复核记录和未解决事项。
6. 全流程不出现授信承诺、自动放款或真实效果数字。
