## 首次运行

在仓库根目录复制 `.env.example` 为本地 `.env`，设置独立的 `SEED_DEMO_PASSWORD`，并确认 `DATABASE_URL` 指向 `xingzhi_dev`，不要连接其他项目的数据库。若该库尚未创建，先执行 `createdb xingzhi_dev`；之后依次运行：

```sh
pnpm install
pnpm db:migrate
pnpm db:seed
pnpm dev
```

`pnpm dev` 同时启动网页、API 与 worker。`pnpm db:migrate` 只应用未执行的顺序 SQL 迁移；`pnpm db:seed` 可重复执行，用于补齐本地测试账号和 A/B/C/D 目录，不写入真实数据。

历史真实模型只读烟测和 T04／T08 方案联调已通过，停止前的 API-24 提供查询与方案助手入口；Pi 依赖已安装。服务端只从本机 `.env` 读取 `DEEPSEEK_API_KEY`，固定 `DEEPSEEK_BASE_URL=https://api.deepseek.com`，当前配置为 `DEEPSEEK_MODEL=deepseek-flash`（DeepSeek V4.1 Flash，用户简称“ds4.1flash”）；累计模型费用上限为人民币 100 元，采用每分钟 10 次、突发 2、同计划并发 1 的常规服务端限流。当前 `deepseek-flash` 的真实模拟业务连续链、固定场景、进程中断与授权连续核对见验证记录第十八至十九节；未配置密钥或人民币预算账本时不会发起外部模型调用。

本阶段还提供 `pnpm typecheck` 和 `pnpm test:targeted`。`pnpm build` 留给首次交付构建或构建路径变更时执行，不作为日常文档／业务检查。

## 测试账号

种子数据使用两个消费者、一个测试商户管理员和一个只读审核者。邮箱分别是 `consumer-a@xingzhi.local`、`consumer-b@xingzhi.local`、`merchant@xingzhi.local`、`reviewer@xingzhi.local`；密码只取自本机 `.env` 的 `SEED_DEMO_PASSWORD`，不写入 Git。

消费者工作台可建立 A/B/C/D 计划，生成和确认购买预览、建单、观察模拟结果、暂停购买、生成变更预览、提交模拟善后，并查看授权、退款批次和当前人工责任。商户工作台可管理命名规则预设、查看取消队列、处理延迟申请、安排固定退款批次及记录人工复核；审核者只显示服务端分配的计划范围。所有写操作由服务端会话、请求来源、幂等键和计划版本共同约束。

## 恢复开发前最近一次已核对与当前仍待放行的范围

下述 S1／S3 内容是停止前最近一次可引用的局部验证，不覆盖停止后写入的交易工具、事件恢复和页面初稿。S1 已实现目录、计划、购买确认、同计划预算占用、暂停、变更确认、善后／查询授权、事件、可恢复 worker 与明确标识的本地模拟付款／关单。S3 在服务端补充商户规则预设、规则自动给出的取消决定、确认总额约束下的固定退款批次、租约版本检查、人工复核任务和 API-25 显式复核，并在网页接入商户规则、取消队列、退款批次、人工任务以及消费者善后事实与授权管理；商户仍独占退款批次执行权，消费者与 Agent 都不能调用该入口。费用退款、两笔各 400 元的分批退款、拒绝、延迟转人工后批准、未知结果保留占用、双 worker 单次领取、付款／关单竞争及 A/B/C/D 整体结构化场景已在本机作定向核对；整体场景最终为 A 保留已付款、B 退款 800 元、C 关单、D 停止且无订单，净支出 500 元、待核对占用 0。审核者工作区还提供 API-15／API-27 的本机 JSON／HTML 脱敏导出，带 24 小时有效期和服务端范围校验。此前新增页面已通过类型检查、首次构建及 320／390／768／1024／1280／1440 像素宽度的浏览器核对，未发现横向溢出或控制台错误；2026-09-12 新增的 API-25 复核按钮尚未进行浏览器交互验收。模拟结果仅用于验证内部状态和恢复路径；它不能证明官方支付、退款或回调能力。

S2 当前仍只实现服务端、数据库和支付适配边界：默认 `PAYMENT_MODE=simulation`，未填齐沙箱配置时拒绝生成官方付款交接或处理渠道通知，不会访问外部网关。沙箱的 `notify_url` 为可选项；本机没有 HTTPS 时，付款返回后由服务端主动查单，只有核对订单号、金额、卖家和交易状态后才更新订单。异步通知验收仍需渠道可访问的 HTTPS 地址，固定域名和云服务器后置。消费者页面已补充付款进度卡片：模拟订单明确不显示官方收银台，沙箱订单才显示受控交接和主动查单入口；页面不把打开付款链接冒充为付款成功。

官方沙箱付款与回调验签，以及拒绝／延迟／未知和恢复竞争的完整验收仍按[分阶段开发计划](docs/03-engineering/development-plan.md)在 S2—S5 推进。Pi 本地确定性循环、费用账本、真实只读／方案联调和局部真实模型执行评测已通过；交易执行工具、事件恢复、T10 复核与变更善后连续链已通过本地受控核对，当前模型模拟连续链、实际进程与独立虚构库恢复已有第十七至十九节证据，官方交易及完整跨端验收仍待补齐。审核行迹导出已提供本机 JSON／HTML 脱敏路径，但尚未纳入 36 项完整验收。领域规则和接口边界以文档中心中的权威文档为准。
