## 一、分层验证

领域测试验证状态、金额、权限和幂等；适配器契约测试验证渠道字段和错误映射；模拟故障验证超时、重复、乱序和重启；Pi／DeepSeek 烟测只验证无资金工具调用、模型错误、429 退避、预算拒绝和会话恢复；官方沙箱验证真实测试接口；连续端到端验证同一可追溯业务运行的购买到退款。既有真实模型烟测均按旧 `deepseek-v4-flash` 记录；当前 `deepseek-flash` 的运行准入、请求体和费用计算已由本地测试核对，尚未重新发起真实付费烟测。模拟和模型烟测可以构造故障，不能替代渠道成功证据或证明 Agent 效果。

详细案例保留在[Demo 与验收](../01-product/demo-and-acceptance.md)，当前共36项：P01—P13、A01—A11、R01—R12，全部属于 P0。P0 同时覆盖费用预览和接受后的部分退款、多次部分退款、商户拒绝／延迟、重复请求、恢复与环境隔离；FR-14 的官方 Agent 支付、小程序和独立商户适配仍为 P1，不进入本轮放行门槛。36 项是放行验收清单，不要求在第一轮开发创建 36 个测试文件；实现过程只为状态、金额、权限和外部适配等有明确回归风险的行为补最少定向测试，沙箱用例以可复核记录完成验收。

## 三、P0 放行门槛

1. 同一可追溯业务运行形成选购、确认、订单、实际沙箱付款、变更确认、全额或部分原单退款与查询证据；允许跨 Agent 会话恢复，不能拼接无关订单。
2. A 保留、B 退款、C 未付关单和 D 停止均有正确依据；无法构造 C 渠道待付款时先解决前置条件，不豁免关单。
3. P0 用例均有可复核实际结果；涉及重复资金、越权、误环境和假成功的缺陷不得带入发布。
4. 页面关闭及后台重启后恢复正确，Agent 不靠持续轮询模型等待退款。
5. 未决资金清晰展示；等待渠道和人工接管不能算全闭环通过。

6. 登录／退出、计划恢复、结构化回退、授权撤回／续期、商户管理、人工任务、移动页面和脱敏导出均可操作；开发计划 S4 页面清单与 Demo 7.4 子场景无缺项。

阶段验收按[开发计划](../03-engineering/development-plan.md)记录。S1—S4 的局部通过不等于 P0 放行，S5 全部门槛通过后才能标记首个完整 MVP／Demo。拒绝取消用例的“行为验证通过”只说明正确展示拒绝，不等于该订单退款成功；完整成功链路仍须独立通过。

## 四、验收记录

按大阶段集中记录日期、适用代码与环境、覆盖案例、实际结果和证据位置；同批次共用信息只写一次。仅有差异时补充角色、前置条件、模型版本、失败步骤和复测关联，不强制逐次填写完整模板或创建缺陷编号。未执行用例不得预填“通过”。

支付证据包另记录 planId、内部订单、脱敏渠道关联号、确认范围、规则版本、实际付款与退款、查询时间、未知操作及金额核对。导出遵守数据保护规则。

### 4.1 证据复用与完成判定

结果增加“未执行”状态。每条结果注明证据层级（静态核对／本地模拟／适配器契约／官方沙箱／连续端到端）及本次覆盖的子场景。静态核对只能证明代码结构和差距，不能记为行为通过；历史记录注明日期及适用版本，相关路径修改后定向复测。阶段表引用这里的实际记录，不在多个入口重复维护测试结论。

每个完整用例列清必验子场景、所需证据、已覆盖部分和缺失部分，全部满足才标记该用例通过。启用异步通知路径时必须补可达性和实际验签证据；未启用时仍按既有案例用隔离契约验证重复、乱序和伪造输入，并明确没有真实通知联调证据。若具体子场景明确要求渠道实测而无法执行，记录阻塞，不以路径可选为由删减 36 项或默记通过。

证据位置应能定位到脱敏记录、测试输出或受控导出；仅有命令名、截图中的“成功”或文档中的口头结论不足以新增通过记录。静态引用写文件及函数，运行记录写实际修订、环境、对象关联和结果。工作区未提交时注明未提交范围，不计算默认文件指纹。

## 五、Agent 效果与交付评审

使用明确取消、部分保留、歧义意图、规则变化和恶意商品描述组成固定案例集，比较 Agent 与结构化表单的任务完成率、错误动作、确认次数、时延与调用成本。先固定评价方法再记录实测，不预填提升比例。

阶段收尾统一核对范围、授权、恢复、证据与剩余阻塞，由实际执行者完成，不设置四轮独立评审。历史证据覆盖 S1 本地实现、S3 本地结构化核心定向链路，以及 S4 的真实只读／方案联调和确认卡片衔接；2026-09-11 恢复开发后新增的局部证据见第十三节。S2 仍只完成沙箱只读查单连通性核验，尚未通过官方付款交易、36 项完整验收或首次交付放行门槛。
