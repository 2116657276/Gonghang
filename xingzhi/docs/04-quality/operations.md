## 一、环境和凭据

本地模拟、官方沙箱与未来正式交易分别隔离数据、应用、凭据和网关；当前文档阶段不创建配置文件。沙箱采用明确允许的网关目标，启动和调用前检查环境一致性；不只依赖前端标签。测试商户身份不能冒充真实品牌。

密钥仅由商户支付适配器读取，不进入用户端、模型上下文、工具返回、普通日志或公开仓库。日志默认脱敏订单与账号，付款入口引用受权限与有效期限制。认证、会话保护和导出访问策略在开发前确认，不以“只有一个用户”豁免鉴权。

## 二、观测与人工接管

| 观测项 | 用途 | 处理原则 |
| --- | --- | --- |
| 暂停受理至生效耗时 | 验证停止新购买的执行路径 | 阈值待评审；记录在途例外 |
| 未知支付／退款数量与年龄 | 防止任务静默丢失 | 超出经确认等待门槛产生人工任务 |
| 重复请求与参数冲突 | 排查幂等问题 | 保留业务编号，不手改成功状态 |
| 通知验签／金额／归属失败 | 排查无效回调 | 拒绝更新并隔离审查 |
| 后台任务积压和领取过期 | 判断恢复能力 | 接管先核对外部结果 |
| Agent 轮次、工具失败和费用 | 控制推理开销 | 到上限结束决策，保持业务任务 |

人工任务必须有对象、原因、证据、责任角色、下一动作和复核时间。人员可重发查询或按同一业务请求重试，不能直接把未知结果改成已退款。人工接管状态面向用户可见。

## 三、故障处置

渠道不可用时停止新增不安全操作、保留未知占用、展示待核对；不自动切换正式环境。模型不可用时保留业务查询与暂停入口，后台继续已授权任务。疑似越权或凭据暴露时暂停相关执行入口，保留证据并由有权限人员处理凭据，不把凭据贴入工单。

部署回退只能回退应用逻辑，不能回滚外部付款。旧程序若不能解释新状态或数据结构，不允许直接回退上线；先停止新购买、排空或接管在途任务，确认兼容性。备份恢复后必须查询渠道补齐备份时间之后的外部事实。

### 4.1 第一开发阶段：本地业务基础纵切

第一阶段的目标是在本机完成可运行的 P0 业务底座，而不是提前宣称已打通支付。范围包括：Vue 3/Vite 响应式页面、Fastify API、PostgreSQL 逻辑表与迁移、消费者／测试商户管理员／审核者的服务端会话、A/B/C/D 测试商品目录、购买与善后授权、购买与变更方案、暂停、订单、业务操作／待发送任务、事件时间线及独立后台执行者。

第一阶段至少应能在本地演示：消费者从目录生成购买方案并确认，系统创建购买授权和订单；暂停后旧授权不能创建新订单；变更方案绑定保留项、取消项和费用；服务重启后可从 PostgreSQL 读取非终态操作与事件。支付适配器只保留可替换契约和本地模拟，不生成沙箱付款、退款或关单通过结论；Pi 运行时和官方支付调用进入后续阶段。

这一阶段只为状态、金额、权限、幂等、暂停竞争和重启恢复等有明确回归风险的行为编写最少定向验证。不得因为验收清单有 36 项，就先批量创建同质测试文件。

当前已完成 P0 开发基线文档并安装全局 TypeScript CLI，不给出未经资源验证的工期或可用性承诺。后续代码变更需要关联需求、影响说明、定向测试证据和评审；破坏性数据变更须说明恢复路径。当前不执行支付；沙箱联调须在账号、设备与通知条件核实并获得授权后进行。
