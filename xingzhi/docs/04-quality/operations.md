## 一、环境和凭据

本地模拟、官方沙箱与未来正式交易分别隔离数据、应用、凭据和网关；本地 S1 已创建被 `.gitignore` 排除的 `.env`，其中包含独立 `xingzhi_dev` 连接、本地测试账号密码，以及用户提供的沙箱应用参数，均只供本机使用。当前先在本机开发，固定域名和云服务器不作为前置条件。沙箱采用明确允许的网关目标，启动和调用前检查环境一致性；不只依赖前端标签。没有 HTTPS 时，本机沙箱付款使用返回页后的主动查单；只有配置 `notify_url` 并做异步通知验收时，才需要渠道可访问的 HTTPS 地址，后续可经用户授权采用临时隧道，或在云服务器部署后配置固定地址。测试商户身份不能冒充真实品牌。

密钥仅由商户支付适配器读取，不进入用户端、模型上下文、工具返回、普通日志或公开仓库。日志默认脱敏订单与账号，付款入口引用受权限与有效期限制。P0 使用预置本地测试账号、服务端会话与固定角色，不开放注册或短信接入；至少准备两名消费者用于越权验证、一名商户管理员及一名只读审核者。密码使用专用密码摘要算法和随机盐，凭据由本地环境提供，不写入仓库。会话存 PostgreSQL，随机会话令牌经 HttpOnly、SameSite Cookie 传递，HTTPS 环境启用 Secure；状态变更接口校验请求来源并防止 CSRF。退出即时失效；会话期限默认 24 小时，和购买／善后授权分别判断，退出登录不撤销已受理业务任务。审核范围由服务端配置。

S4 只允许服务端读取 `DEEPSEEK_API_KEY`；模型配置固定为 `DEEPSEEK_BASE_URL=https://api.deepseek.com` 与 `DEEPSEEK_MODEL=deepseek-v4-flash`。密钥缺失、基地址不是允许值、预算账本不可用时，拒绝发起外部模型请求。Pi 运行层不启用 shell、任意 HTTP、任意文件写入或支付密钥工具。

## 二、观测与人工接管

| 观测项 | 用途 | 处理原则 |
| --- | --- | --- |
| 暂停受理至生效耗时 | 验证停止新购买的执行路径 | 本地目标与计时边界见下方参数表；记录在途例外 |
| 未知支付／退款数量与年龄 | 防止任务静默丢失 | 超出经确认等待门槛产生人工任务 |
| 重复请求与参数冲突 | 排查幂等问题 | 保留业务编号，不手改成功状态 |
| 通知或查单的签名／金额／归属失败 | 排查无效渠道事实 | 拒绝更新并隔离审查 |
| 后台任务积压和领取过期 | 判断恢复能力 | 接管先核对外部结果 |
| Agent 轮次、工具失败和费用 | 控制推理开销 | 到上限结束决策，保持业务任务 |

人工任务必须有对象、原因、证据、责任角色、下一动作和复核时间。人员可重发查询或按同一业务请求重试，不能直接把未知结果改成已退款。人工接管状态面向用户可见。

## 三、故障处置

渠道不可用时停止新增不安全操作、保留未知占用、展示待核对；不自动切换正式环境。模型不可用或预算达到 ¥100 时保留业务查询与暂停入口，后台继续已授权任务。疑似越权或凭据暴露时暂停相关执行入口，保留证据并由有权限人员处理凭据，不把凭据贴入工单。

部署回退只能回退应用逻辑，不能回滚外部付款。旧程序若不能解释新状态或数据结构，不允许直接回退上线；先停止新购买、排空或接管在途任务，确认兼容性。备份恢复后必须查询渠道补齐备份时间之后的外部事实。

## 四、P0 本地运行参数

下列参数是按已授权的首版完整 Demo 目标选定的本地开发默认值，不是渠道要求、生产服务承诺或实测结果。实现时集中配置，不在各模块各写一份；故障用例可使用独立测试配置加速时间，不修改业务时钟事实。

| 项目 | 本地默认值与处理 |
| --- | --- |
| 报价／待确认方案有效期 | 10 分钟，并取商品规则、订单状态与授权约束中更早的失效条件；规则变更仍触发版本校验 |
| 暂停响应目标 | 普通本地单用户场景下，从服务端收到请求至暂停提交并返回不超过 1 秒；不含自然语言识别和客户端网络，实测未达标则记录原因并修复 |
| 后台领取 | 空闲扫描 1 秒，领取租期 60 秒；长任务每 20 秒续租，失去领取版本不可提交结果 |
| 外部请求超时 | 默认 15 秒；写请求超时转未知，不能按失败自动重发 |
| 可安全重试的任务 | 最多 3 次自动重试，间隔 5／15／30 秒；请求已受理或未知时先查原单，遵守适配器重试判据 |
| 渠道状态查询 | 本地模拟默认 10／30／60／120／300 秒逐步等待，之后每 300 秒一次；沙箱实际配置须在 S2 按所用官方接口复核后固定，采用更严格的等待和限频要求 |
| 人工接管 | 明确标识为本机 `PENDING`／`UNKNOWN` 的模拟结果立即生成唯一人工任务，以便核对状态与权限链路；实际渠道未知、商户延迟超过 30 分钟或安全重试耗尽时才生成任务并暂停自动轮询／重试。两种情况均保留占用和未决状态；之后按原操作由有权人员复核，默认下一次人工复核时间为 24 小时内，不承诺渠道在该时限完成 |
| Pi 单轮边界 | 最多 8 次模型调用、20 次工具调用、总运行 120 秒；每次调用超时 30 秒；达到任一上限则结束本轮、保留业务任务并展示原因 |
| 模型费用 | 本地开发／验收环境累计上限为人民币 100 元；按 DeepSeek 响应 usage 与公开价格估算，直接按官方人民币费率记账，无需汇率；剩余预算不足时拒绝新调用，重置账本必须人工记录，不能通过重启绕过 |
| Agent 入口限流 | 已认证消费者的 Agent 运行请求采用令牌桶，默认每分钟 10 次、突发容量 2；同一计划同时最多 1 个活动运行；限流发生返回 429 与等待提示，不自动改写请求 |
| 上游错误退避 | DeepSeek 429 若返回 `Retry-After` 则遵守，否则使用本地退避；最多 3 次带抖动退避，仍失败转为可重试的模型错误；不因 429 自动切换正式环境、模型或支付参数 |

## 五、P0 数据、备份与导出

本阶段仅采集测试账号及必要业务记录，不采集真实身份证明、银行卡或旅客资料。以下为本地 Demo 数据政策；正式公开服务、真实用户数据或真实资金场景在引入前另行确定适用政策。

| 数据或动作 | 本地处理规则 |
| --- | --- |
| 会话和模型交流 | 会话到期失效；对话与普通脱敏运行日志保留 30 天后可清理；确认和资金事实不随聊天删除 |
| 模拟业务数据 | 所有关联动作终态且无未决事项后满 30 天可清理；仅本地管理员明确选择的模拟计划允许整组重置 |
| 沙箱订单、确认和核验依据 | 所有关联事项结束后保留至少 90 天；未决操作、相关授权与证据不按期限自动删除 |
| 清理执行 | P0 不建立自动批量删除服务；由管理员显式选择环境和计划，检查关联未决事项、备份与引用后执行，记录清理范围；审核者不能清理 |
| 备份 | 进行沙箱联调的当日及破坏性迁移前制作本地备份；保留最近 7 份，清理旧备份须明确选择；凭据独立保存，备份不进入 Git |
| 恢复核验 | 在独立测试库恢复一份备份，核对计划、订单、任务关联；恢复后先按渠道补齐外部事实，不能直接重放资金写请求 |
| 行迹导出 | 首版提供可读 HTML 与结构化 JSON；服务端鉴权下载，引用 24 小时过期，默认脱敏，不开放匿名公开分享；用户下载后自行分享的副本无法由系统远程撤回 |

### 5.1 环境切换与恢复操作边界

切换 `PAYMENT_MODE` 不迁移既有订单的环境，不把模拟订单转换成沙箱订单。启用沙箱前先关闭开发计划列出的环境分派缺口，并为该环境使用独立数据库或已验证的等效隔离；当前表中存在环境字段不等于隔离已经验收。切换前确认 API 与 worker 配置一致，列明未决操作；旧环境任务保留在原环境处理，不由新适配器接管。

后台恢复前先核实任务类型、环境、原业务编号、领取版本和最后发送阶段，再恢复到期任务。当前模拟与渠道任务已在同一结果事务内检查领取版本；出现业务已成功但任务未完成、事件缺失或金额不一致时，仍按原操作核验并保留证据，不手改成功状态或清库重演。真实长时间中断和备份恢复仍需验收，见[数据与事件](../03-engineering/data-and-events.md)。

参数表是目标运行基线，不代表所有后台退避、自动核对、模型入口或清理能力均已完成。当前 API-25 在沙箱模式创建并执行受控复核任务，模拟对象仍转人工任务；API-24 只读入口和限流已实现，交易写工具与事件恢复已接入但仍需按验证策略完成剩余验收；上游 429 退避已完成本地受控验证，每项运行能力以开发计划与实际验证记录为准。
