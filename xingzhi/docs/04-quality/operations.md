更新日期：2026-09-17。状态：原运行环境继续使用；001—029 已应用，A00—A06、B00—B07 与 M1 补充收口核心后端已接入，消费者 HTTP 连续验收已按[验证策略第十四节](../04-quality/verification.md)在隔离数据库完成。日常仍使用 simulation；微信小程序和新流程 sandbox 连续演示尚未完成。

## 一、环境与数据来源

前端 M2 已可开工（M1 收口通过）。Demo 数据准备使用显式创建的新隔离场景：在仓库根目录执行 `pnpm --filter @xingzhi/server db:seed:consumer-scenario <场景标识> <服务日期 YYYY-MM-DD>`，密码取自本机 `SEED_DEMO_PASSWORD`；同标识重复执行不覆盖状态、不延长报价、不复活撤回账户，旧场景过期须新建场景。已过期的原快照、撤回账户和旧报价不会通过重新运行种子恢复。新场景不继承旧订单进度，同一次支付至退款演示必须沿同一场景；保留历史订单、渠道证据、费用和本机私密配置。

微信小程序首版演示与日常开发使用 `PAYMENT_MODE=simulation`，独立的支付宝渠道连续演示才按授权配置 sandbox。API 与 worker 配置一致，按订单保存的环境分派，切换不修改旧订单环境。限定本次任务范围，不能让旧任务被新环境接管。

新银行账户、收支、还款和商户资料为虚构测试数据，页面和导出标识来源、基准时点及可见范围。支付宝沙箱余额不是主银行卡余额，渠道退款成功不是银行到账证明；测试流水联动必须标为模拟，不能写成银行真实回执。

## 二、凭据和权限

本机 `.env` 与 `.local-secrets` 继续由 Git 忽略。买卖家凭据只用于受控官方沙箱浏览器操作，不进入业务模型、普通日志、文档和仓库。模型密钥只由服务端读取，数据快照不得带银行卡号、身份资料或完整支付链接。

保留测试会话和消费者／商户／只读审核权限。现行会话仍是网页 Cookie 与 Origin；小程序消费者令牌接入按[API 契约 1.3](../03-engineering/api-contract.md#13-m2-小程序会话接入待实现)在 M2.1 实施，尚无可调用的新会话入口。页面切换不改变角色；退款由商户执行。用户确认购买和调整范围，付款遵守渠道要求及既有最终提交确认；本轮文档不授权任何交易。

## 三、SQL、种子和恢复

新 SQL 采用增量迁移；代码基线含 001—029，本机 `xingzhi_dev` 已应用全部 29 条迁移（029 先在集中验收的隔离数据库应用，随后于 2026-09-16 应用到本机开发库）。已应用迁移不重写，不默认删除现有表或清空 `xingzhi_dev`。029 为 M1 收口新增表（分类展示覆盖、Agent 产物、订单善后预览、隔离场景登记）和约束，不改写 001—028 与历史交易。若后续确需破坏性变更，先列明数据映射和备份恢复方案，确认该动作的授权范围后执行。

新主演示种子与历史回归样本使用独立命名和对象关联。B00 目录报价使用独立初始化入口，固定写入 2 条 Demo 报价；隔离场景入口按场景另建匹配日期的报价。A00 稳定资金样例与隔离场景按需使用，实际本机数量以初始化输出和目标数据库查询为准，不在长期文档中固定。重复加载应复用目标测试样本，不覆盖已交易订单快照，不重置未知操作和模型费用。默认种子不执行付款或模型调用。清理只处理显式选择的模拟样本及可安全删除关联；未决对象不清除。

恢复备份时使用独立数据库，先停止目标服务与外部调用，再核对订单、确认、任务和原业务号。可能已发送的关单／退款先查原号，不能因本地记录缺失就重新发送。原详细恢复与实际演练记录见[历史验收](../archive/transaction-verification.md)。

## 四、运行资源与故障

沿用现有模型配置、锁文件、每计划单运行、轮次／时间限制和共享人民币 100 元费用预算。预占不是实际费用，无 usage 保留待核对；不能通过新种子或重启清零。模型失败时结构化查询、暂停与已确认业务处理仍可用。

未知支付或退款保留原操作和金额事实，不把超时当明确失败。模拟付款／关单未决保持原操作供显式复核，模拟退款未决保留商户责任。人工接管不是退款成功。

本次文档整理不升级依赖、购买域名、发布服务或新增隧道／通知系统。后续 M2.1 需落实 AppID、手机可访问 API、HTTPS／合法域名及体验成员；这是待执行的环境准备，不是现有部署能力，见[小程序方案](../03-engineering/miniapp-frontend.md)。现有沙箱可通过主动查单核验，实际通知能力尚未验证。启动命令与现有账号入口见[本地说明](../../README.md)，验收节奏见[开发计划](../03-engineering/development-plan.md)。
