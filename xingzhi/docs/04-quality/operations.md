# 运行与数据操作边界

更新日期：2026-09-15。状态：原运行环境继续使用；新账户与种子迁移尚未执行。本轮仅文档。

## 一、环境与数据来源

日常使用 `PAYMENT_MODE=simulation`，演示交易才按授权切换 sandbox。API 与 worker 配置一致，按订单保存的环境分派，切换不修改旧订单环境。限定本次任务范围，不能让旧任务被新环境接管。

新银行账户、收支、还款和商户资料为虚构测试数据，页面和导出标识来源、基准时点及可见范围。支付宝沙箱余额不是主银行卡余额，渠道退款成功不是银行到账证明；测试流水联动必须标为模拟，不能写成银行真实回执。

## 二、凭据和权限

本机 `.env` 与 `.local-secrets` 继续由 Git 忽略。买卖家凭据只用于受控官方沙箱浏览器操作，不进入业务模型、普通日志、文档和仓库。模型密钥只由服务端读取，数据快照不得带银行卡号、身份资料或完整支付链接。

保留测试会话和消费者／商户／只读审核权限。页面切换不改变角色；退款由商户执行。用户确认购买和调整范围，付款遵守渠道要求及既有最终提交确认；本轮文档不授权任何交易。

## 三、SQL、种子和恢复

新 SQL 采用增量迁移，首次在隔离测试库应用；已应用迁移不重写，不默认删除现有表或清空 `xingzhi_dev`。若后续确需破坏性变更，先列明数据映射和备份恢复方案，确认该动作的授权范围后执行。

新主演示种子与历史回归样本使用独立命名和对象关联。重复加载应复用目标测试样本，不覆盖已交易订单快照，不重置未知操作和模型费用。默认种子不执行付款或模型调用。清理只处理显式选择的模拟样本及可安全删除关联；未决对象不清除。

恢复备份时使用独立数据库，先停止目标服务与外部调用，再核对订单、确认、任务和原业务号。可能已发送的关单／退款先查原号，不能因本地记录缺失就重新发送。原详细恢复与实际演练记录见[历史验收](../archive/transaction-verification.md)。

## 四、运行资源与故障

沿用现有模型配置、锁文件、每计划单运行、轮次／时间限制和共享人民币 100 元费用预算。预占不是实际费用，无 usage 保留待核对；不能通过新种子或重启清零。模型失败时结构化查询、暂停与已确认业务处理仍可用。

未知支付或退款保留原操作和金额事实，不把超时当明确失败。模拟付款／关单未决保持原操作供显式复核，模拟退款未决保留商户责任。人工接管不是退款成功。

不因文档迁移升级依赖、增加云服务、域名、隧道或通知系统。现有沙箱可通过主动查单核验，实际通知能力尚未验证。启动命令与现有账号入口见[本地说明](../../README.md)，验收节奏见[开发计划](../03-engineering/development-plan.md)。
