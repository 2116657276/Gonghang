## 队员方案的吸收与取舍

团队会话中提供、但未纳入仓库的附件《行止_项目功能计划.md》仅作为建议来源，不直接作为执行规则。吸收生活目标、资金可行性判断、方案取舍、变化解释与轻量复盘；保持本项目的真实确认和既有交易闭环。已采纳的决定全部固化在现行 PRD、领域规则和接口契约中，后续开发不依赖访问该附件。

| 建议 | 处理方式与理由 |
| --- | --- |
| 从生活目标出发 | 纳入首版；可先表达目标并生成草稿，再补账户及必要安排。数据不足不输出确定资金结论 |
| 金融判断先于商品推荐 | 纳入首版；先显示当前约束和缺口，再比较登记商品，保留用户选择 |
| 预算拆分、必须项与可调整项 | 纳入首版；作为现有计划及项目的少量属性，不另建目标系统 |
| 稳健／均衡／体验三套方案 | 收敛为有足够合格候选时至少两套有实质差异的比较；不硬凑三套，不把超过约束的方案默认当可执行 |
| 可解释风险提醒与决策记录 | 纳入首版；显示具体日期、金额和依据，记录事实版本、规则结果及授权；不保存或展示模型私有思维链 |
| 消费后复盘 | 纳入轻量派生视图；比较原计划与实际已付、已退、净额和未决，不新增自动偏好学习 |
| 高确定性收入加入生活可支配额度 | 不采用原公式；预计收入仅进条件情景，当前金额标签用“当前可安排金额”，并列数据范围和前提，不保证安全可花 |
| 持续运行／自动重规划 | 改为事实变化触发规则重算和待确认建议，等待时结束模型运行；不自动取消、重购、借贷或还款 |
| 多 Agent、长期资金池、储蓄理财联动 | 首版不采纳；复用单 Agent、业务服务和现有计划，避免范围膨胀 |
| 支付订单放到后续阶段 | 不采纳；已有能力继续作为本次可执行闭环，最终以沙箱验证 |
| 附件金额与竞品比较 | 不直接采用；统一使用可复算样例，未核实的竞品结论不写成项目事实 |

这些取舍不增加独立验收流水线，新增细节并入现有 N 案例和 M1—M3。B00—B02 已完成接口独立实现，但不因此把新 N 案例、真实资金服务或完整消费者闭环标记为通过。
