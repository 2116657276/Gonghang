## 一、已确认决定

| 编号 | 决定 | 依据与影响 |
| --- | --- | --- |
| DEC-01 | 行止第一优先，潮汐与绿链备选 | 用户明确决定；不并行建设三个项目 |
| DEC-02 | 先统一 P0 开发基线，再启动本地实现 | 已安装全局 TypeScript CLI；当前尚不安装项目依赖或执行支付联调；文档确认后可按 P0 基线开发，支付联调和真实资金须另行授权 |
| DEC-03 | 可以复用成熟技术；同类获奖不自动淘汰 | 来源、许可、自主贡献与效果分别说明 |
| DEC-04 | 必须完整购买—付款—变更—取消／退款—结果核验 | 用户明确“必须做到完整闭环”；替代原仅演示付款退款的简述 |
| DEC-05 | P0 首发为响应式网页，小程序后续 | 网页覆盖电脑与手机展示；小程序不阻断基础闭环 |
| DEC-06 | 官方沙箱为 P0 交易验证基线，普通付款入口先行 | 纯模拟不计交易通过；官方 Agent 支付是独立增强；账号不适用则报告阻塞重评 |
| DEC-07 | P0 为模块化单体、持久数据库和后台执行者 | 一个业务后端与后台执行者共享数据库；不拆微服务 |
| DEC-08 | 首版使用自己的测试商户承接购买与善后 | P0 固定 A 去程交通 420 元、B 住宿 880 元、C 景点 180 元、D 接驳 120 元；总购买上限 3000 元、授权有效期 24 小时，仅作为测试参数 |
| DEC-09 | 使用累计购买上限，退款不自动恢复购买空间 | 需要再次购买时必须取得新的购买确认；不以退款重置旧授权账本 |
| DEC-10 | 测试商户按已配置规则自动批准或拒绝取消，并由商户执行原单退款 | 用户确认不等于商户退款权；费用、拒绝和延迟均保留明确状态与人工路径 |
| DEC-12 | 自定义 Pi agent-core 单 Agent、多工具 | 用户明确选择；不叠加 LangGraph、不深度派生完整编程助手；见 ADR |
| DEC-13 | 先整合现有仓库文档，再建行止体系 | 已完成顺序调整；保留必要历史研究，清理重复和无关导航 |
| DEC-15 | P0 首发为响应式网页、TypeScript 模块化单体、Vue 3/Vite 前端、Fastify 业务 API、PostgreSQL 和同库独立后台执行者 | PostgreSQL 是授权、订单、支付、退款和任务的唯一业务事实库；本机 Redis 仅可按需用于非关键缓存或限流，不作为 P0 依赖、队列或交易状态来源；不引入微服务、消息队列、多 Agent 或跨端框架作为首发前提 |
| DEC-16 | 首次 P0 包含费用预览、用户接受后的部分退款、多次部分退款、商户拒绝／延迟和明确失败处理 | P0 目标是测试商户内完整、可解释的购买与善后闭环；不扩展到真实商户、钱包、分账或自动垫付 |
| DEC-17 | P0 使用服务端会话识别消费者、测试商户管理员和只读审核者 | 身份与角色不能由前端切换或模型参数决定；具体身份提供者可在保持该契约前提下实现 |
| DEC-18 | 购买授权、善后授权和查询授权分开保存 | 购买确认创建购买授权；变更确认创建订单范围内的善后授权；暂停只影响购买授权，撤回查询权限停止新增受托查询 |
| DEC-19 | 第一开发阶段先完成本地 P0 业务基础纵切 | 建立 Vue 3/Fastify/PostgreSQL 本地应用、服务端角色、A/B/C/D 测试目录、授权／暂停／方案／订单／任务持久化与本地恢复；不把本地模拟写成支付沙箱通过 |

完整闭环已作为项目目标确认，但不等于确认每项金额、时限或技术组件。日期均为本次整理记录日期；不编造独立签字、人员或联调结论。
