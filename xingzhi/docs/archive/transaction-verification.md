## 三、P0 放行门槛

1. 同一可追溯业务运行形成选购、确认、订单、实际沙箱付款、变更确认、全额或部分原单退款与查询证据；允许跨 Agent 会话恢复，不能拼接无关订单。
2. A 保留、B 退款、C 未付关单和 D 停止均有正确依据；无法构造 C 渠道待付款时先解决前置条件，不豁免关单。
3. P0 用例均有可复核实际结果；涉及重复资金、越权、误环境和假成功的缺陷不得带入发布。
4. 页面关闭及后台重启后恢复正确，Agent 不靠持续轮询模型等待退款。
5. 未决资金清晰展示；等待渠道和人工接管不能算全闭环通过。

6. 登录／退出、计划恢复、结构化回退、授权撤回／续期、商户管理、人工任务、移动页面和脱敏导出均可操作；开发计划 S4 页面清单与 Demo 7.4 子场景无缺项。

阶段验收按[开发计划](../03-engineering/development-plan.md)记录。S1—S4 的局部通过不等于 P0 放行，S5 全部门槛通过后才能标记首个完整 MVP／Demo。拒绝取消用例的“行为验证通过”只说明正确展示拒绝，不等于该订单退款成功；完整成功链路仍须独立通过。
