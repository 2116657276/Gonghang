## 一、文档职责与执行边界

产品范围由 [PRD](../01-product/prd.md) 定义，N01—N12 判据由 [Demo 与验收](../01-product/demo-and-acceptance.md)维护，金额、来源及权限原则见[领域规则](../02-domain/rules-and-state.md)。当前后端任务、月度数据模型、A/B 交接和目标接口以 [A/B 后端总方案](../../行止_AB后端开发总方案_现状接口数据库任务.md)为唯一实施基线，共享代码 `packages/contracts/src/consumer-backend.ts` 表示已经落入代码的字段。总方案标记的待补类型仍需开发，不得声称已经可用。旧接口与数据文档保留历史交易说明和早期结构参考，不再另行规定新后端任务。

M1 表示整个后端大阶段；A00—A06 与 B00—B07 是 M1 内的分工，B 三批交付不是另一套项目阶段。M1 核心领域链已有验证，但后端补充收口尚未实施；收口集中验收通过后才冻结 M2 联调契约；M3 负责连续沙箱演示、用户观察和交付。

复用 Fastify、PostgreSQL、Pi、现有会话、幂等及支付适配。日常使用 simulation，录制 Demo 时使用获授权的 sandbox；真实银行接入与宿主不作为受控原型的开工前提。模型继续使用现有共享费用上限，不重置历史费用。A00 资金样例不随迁移自动加载，需通过独立种子按需初始化。

### 数据与样本边界

保留原订单、支付尝试、确认、授权、退款、任务、幂等和费用事实。已应用的 001—028 不改写、不清库。新消费者预算只写 `budget_periods/budget_items`，旧 `cashflow_plans/items` 不双写。

A 提供资金样例，B 提供独立稳定 code 的商品与报价，公共 seed 由阶段 0 约定的合并人落入。新初始化不调用会覆盖或重新激活旧 A/B/C/D 商品的路径。固定场景日期和报价有效期在初始化时明确，GET 不移动日期或重新生成报价；报价到期需要显式受控刷新并生成新记录，保留原证据。

### 失败、恢复与回退

增量迁移先在隔离库完成。现有 `db/migrate.ts` 按文件名顺序执行，每个文件和对应 `schema_migrations` 登记在同一事务中；当前文件失败回滚，先前文件仍已提交。执行器仅按文件名跳过已应用迁移，因此必须追加新编号，不能改写旧文件期待自动生效。失败后检查已提交部分和迁移编号，不手动标记成功，不以删除旧表重试。将来对已有数据进行破坏性清理前，必须具备已核对的目标范围与可恢复备份；当前迁移以新增和兼容列为优先，不预设必须清库。

应用切换前暂停售出入口并核对在途 worker；新程序仅恢复自己可解释的任务。需要回退应用时，保留新增表和事实，先确认旧程序能否安全读取新列及状态；不默认执行反向删表迁移。凡已发到渠道的动作不能通过数据库回滚撤销，先按原单核对并交接。

M1 的评审出口包括迁移映射、字段契约、样本说明、金额及权限判据和集中结果。没有真实银行接口不构成这一阶段的阻塞；未知银行字段不伪造为已授权、已读取或零余额。

## 三、M2：统一前端与接口联调

| 小阶段 | 工作与交付物 |
| --- | --- |
| M2.1 工作区 | 主账户及可见范围、收支、还款、近期安排、当前计划和对话；空状态可提出需求；撤回账户显示状态、撤回时间和最后历史快照，不再作为可选主账户 |
| M2.2 选择与调整 | 方案预算拆分、必须／可调整项、候选比较替换、条件可行性、确认、付款、变更选项、退款等待、决策摘要和轻量复盘 |
| M2.3 配套 | 复用登录、刷新恢复、结构化回退；后台保留受控目录和善后职责，历史角色权限继续隔离；新产品只建设消费者工作区 |

**集中验收：** 受影响类型检查与浏览器连续流程，覆盖必要角色权限、刷新恢复和代表性窄屏。只对联调暴露并修复的后端路径复测，不无条件重跑所有历史检查。
