## 一、执行边界

产品范围见[PRD](../01-product/prd.md)，新验收见[Demo](../01-product/demo-and-acceptance.md)。旧后端 1.1—1.4 已有历史证据，但新账户与资金规划仍需后端工作；不能沿旧安排直接开始前端重构。旧 S 编号只作历史引用。

后端负责 `apps/server`、`packages/contracts`、SQL 迁移、种子、worker 和模型／支付适配；M1 统一验收后，前端负责 `apps/web` 的统一工作区与交互，只消费服务端事实。沿用已有框架、任务和会话，不新增通用财务引擎、银行适配平台、测试框架、CI 或复杂缓存重试。

日常使用模拟支付，演示才使用获授权的沙箱交易。真实银行接口、宿主和履约不作为受控 Demo 门槛。模型费用沿用现有共享人民币 100 元上限，不以新场景重置历史费用。

### M1 迁移的具体实施顺序

| 顺序 | 操作 | 结束条件与失败处理 |
| --- | --- | --- |
| 1 盘点 | 对照当前 001—012、实际读写服务和种子列出表／字段映射，识别已有订单、未决操作与模型费用 | 明确哪些表不动、哪些新增、哪些列只增不删；不读取或导出不必要秘密 |
| 2 增量结构 | 从下一未用编号追加账户、流水、还款、规划及消费计划关联，财务及计划关联先落地；目录字段、food 类型与交易门禁在 M1.3 同步实施，既有记录采用明确历史默认值 | 新表可创建，旧行可读取，不能把没有来源的旧计划猜测关联到新账户 |

| 4 资金服务 | 实现基准余额和日期计算、账目覆盖关联、同账户多计划、规划版本；先由结构化输入证明算得一致 | 600／120／280 静态样例及支付后的等价口径成立；预计收入和渠道退款不能自动改变银行余额 |
| 5 接口与 Agent | 补资金读写、账户撤回、空状态目标草稿和候选接口；允许 Agent 按用户明确表达先记录无账户非执行草稿，但商品选定、active 目标变化和交易确认分别由结构化用户入口完成；所有购买确认和新建单入口接入同一资金准入，不留下旧路由绕过 | 撤回后所有新购买入口返回统一错误且历史善后可用；规划版本变化可重新预览；模型不会替用户选择或确认，不读取完整账户凭据 |
| 6 调整衔接 | 接入资金变化、原单关单退款与模拟流水关联；记录事实版本、选择理由和变动差异，完成后派生计划／实付／已退／净额复盘；保留历史已受理任务的处理路径 | 新链不会改变历史业务号，不重新发送可能已发资金操作，明确测试流水和渠道证据 |

### SQL 和种子清理范围

保留原订单、支付尝试、确认、授权、退款批次、任务、幂等和费用事实；旧目录可改为不参与新推荐，但不能删除被订单引用的商品或改写订单原报价。现有 `db/seed.ts` 会按商品 code 覆盖 A/B/C/D 的价格、规则和模拟结果，并重新设为 active；新种子必须取消这种默认覆盖和激活，只在明确选择历史回归夹具时使用旧样本。旧计划没有资金规划关联时作为历史记录保留；对新的购买操作必须明确关联新规划并重新确认，不把“兼容旧接口”当作省略准入的理由。

测试数据主要重写的是主演示的账户、流水、还款、目录、用户安排和事件输入，不是用预置已支付／已退款状态代替主闭环。必要异常夹具可以预置状态，但与连续演示分开命名、分开记结果。首版不开发可任意修改全库的重置后台。

新快照采用明确的场景基准日和时区，种子把相对日期展开成实际日期；避免每次读取时移动基准或让样例自然过期。具体表字段及来源关联由[数据设计](data-and-events.md)唯一维护，不在本计划复制 SQL 定义。

### 失败、恢复与回退

增量迁移先在隔离库完成。现有 `db/migrate.ts` 按文件名顺序执行，每个文件和对应 `schema_migrations` 登记在同一事务中；当前文件失败回滚，先前文件仍已提交。执行器仅按文件名跳过已应用迁移，因此必须追加新编号，不能改写旧文件期待自动生效。失败后检查已提交部分和迁移编号，不手动标记成功，不以删除旧表重试。将来对已有数据进行破坏性清理前，必须具备已核对的目标范围与可恢复备份；当前迁移以新增和兼容列为优先，不预设必须清库。

应用切换前暂停售出入口并核对在途 worker；新程序仅恢复自己可解释的任务。需要回退应用时，保留新增表和事实，先确认旧程序能否安全读取新列及状态；不默认执行反向删表迁移。凡已发到渠道的动作不能通过数据库回滚撤销，先按原单核对并交接。

M1 的评审出口包括迁移映射、字段契约、样本说明、金额及权限判据和集中结果。没有真实银行接口不构成这一阶段的阻塞；未知银行字段不伪造为已授权、已读取或零余额。

| 已收口问题 | 确定处理 |
| --- | --- |
| 空状态与旧计划 | 新目标用 draft，可无账户或商品；历史计划为 legacy，不猜测关联，不改写原订单 |
| 未知预算 | 目标预算为可空独立字段；3000 元历史购买上限不作为用户输入 |

| 候选选中与替换 | 明确 selections 接口及目录 ID／计划项 ID；仅编辑无订单项，旧报价随版本失效 |
| 商品可执行范围 | food 同步数据库与共享类型；listing、unbooked 无可执行报价、确认或建单权限 |
| 撤回账户范围 | 固定撤回接口只改状态并推进相关规划版本；禁止刷新、创建／关联规划及新报价、购买预览、确认、建单和首次付款交接；历史读取与已受理善后继续 |
| Agent 写入范围 | 用户原消息可形成非执行 draft；Agent 不直接选定商品或修改 active 目标，商品选择与购买确认分别由结构化用户入口完成 |
| 去重与来源 | 财务来源按表使用子集，账户／快照／流水不接受 user_input；支付环境独立；流水覆盖、订单关联、账单包含分期按事实只计算一次 |
