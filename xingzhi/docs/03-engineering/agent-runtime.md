## 一、运行原则

每个会话只有一个活动决策循环。首版固定使用 `@earendil-works/pi-agent-core@0.85.1` 与配套 `@earendil-works/pi-ai@0.85.1`，当前模型为 DeepSeek V4.1 Flash，官方 OpenAI 兼容 API 标识为 `deepseek-flash`（用户简称“ds4.1flash”），服务地址为 `https://api.deepseek.com`。运行准入、Pi 模型对象、烟测入口、请求体夹具和人民币费率均已切换并作本地核对；当前模型固定业务场景、真实模型进程中断及授权连续样本已有记录，多场景稳定性和官方交易仍待完成。既有旧模型业务证据仍保留历史属性。版本以精确版本写入依赖和锁文件；选型依据与核对日期见[证据登记](../05-research/evidence-register.md)。

Pi 只使用本项目定义的 T01—T10 工具，不提供 shell、任意 HTTP、任意文件读写、密钥读取或商户原始退款工具。上游 Pi 不负责业务权限、支付一致性或资金账本；本项目的服务端必须在工具执行前后再次校验身份、授权、金额、环境、版本和幂等。工具返回结构化事实与来源，模型负责解释；文字“确认成功”不能取代用户确认接口。Pi 主机不加载完整编程助手的默认工具，若未来扩大工具范围，必须先增加隔离方案和安全评审。

## 二、工具目录

| 工具 | 输入 | 输出 | 控制 |
| --- | --- | --- | --- |
| T01 search_catalog | 类别、日期、需求约束 | 商品、价格与规则引用 | 只读；价格由商户返回 |
| T02 get_plan_orders | 当前计划标识 | 可访问的订单、付款与退款快照 | 只读；后端绑定用户 |
| T03 get_cancellation_quote | 订单标识 | 可退金额、费用、有效期与规则版本 | 只读；不等于批准退款 |
| T04 propose_purchase | 当前计划项标识列表（itemIds） | 服务端计算的购买方案及确认卡片 | 写草稿；不产生购买授权 |
| T05 create_order | 已确认方案标识 | 订单或冲突原因 | 写操作；重查授权、报价及预算 |
| T06 request_payment | 订单标识 | 受控付款交接引用或既有处理状态 | 写操作；秘密链接不回灌模型 |
| T07 pause_purchases | 计划或节点范围、用户请求关联 | 生效版本、暂停范围、在途清单 | 服务端核对明确用户指令；有独立按钮入口 |

| T09 submit_change | 已确认变更方案标识 | 处理任务与受理状态 | 写操作；逐订单检查，不直接暴露商户退款 |
| T10 get_operation_status | 已有操作标识；普通用户消息可明确请求复核 | 已知状态、来源时间、跟踪权限、责任与后续动作 | 默认只读已知快照；普通用户消息的 `requestRecheck=true` 经过 API-25 的查询授权与用途校验，事件恢复不提供主动复核参数；API-06R 由消费者付款页面触发，不作为 T10 的直接调用入口；GET 不隐式访问渠道 |

用户确认接口不是 Agent 工具。商户退款执行同样不在此目录。T07 不允许仅因外部商品文本要求暂停而生效；自然语言含糊时澄清，独立按钮路径完全不经过模型。

## 三、循环与等待

运行状态为 READY、RUNNING、WAITING_USER、WAITING_EXTERNAL、COMPLETED、FAILED 或 CANCELLED。它们只表示 Agent 运行，不表示订单与退款终态。需要确认时持久化方案并结束本轮；收到有效确认后从最新业务快照开始下一轮。需要渠道核对时交给后台任务，不在内存中无限等待。

模型调用前注入已认证范围、当前计划、有限的订单快照、未决操作、规则来源和当前允许工具；不注入密钥、验证码、付款会话或完整渠道回执。摘要可压缩聊天，不能压缩掉方案版本与操作关联。恢复后重新读取业务事实，不照着旧摘要重放写工具。

## 四、执行控制

独立只读查询可以并行；同一授权和订单的写操作受控串行。Pi 的执行前钩子用于快速拒绝，但业务服务必须再次验证身份、授权、参数、金额、环境和幂等。不同会话和后台执行者的并发靠数据库规则，而不是单循环假设。

所有工具使用运行时字段校验。失败返回明确类别、是否可重试和既有操作标识；结果未知时返回待核对，不诱导模型改参数重试。超出模型轮次、调用次数、费用预算或运行时限后停止决策，保留任务并提示用户。模型调用采用常规服务端限流：按已认证消费者使用令牌桶，默认每分钟 10 次 Agent 运行请求、突发容量 2；同一计划同时只允许 1 个活动运行；收到上游 429 时如响应包含 `Retry-After` 则遵守，否则按本地退避策略等待，最多作 3 次带抖动退避，不把 429 当作可更换参数的理由。项目累计模型费用上限为人民币 100 元；费用账本和剩余预算在每次调用前后检查，预计超限时直接拒绝调用。具体参数见[运行文档](../04-quality/operations.md)。授权到期后的既有事实读取与新增受托查询按领域规则区分，不以善后授权绕过已撤回的查询授权。

取消 Pi 运行只取消尚可取消的推理或本地工具等待，不代表已经发出的外部调用被撤销，也不删除已受理任务。即使模型不可用，查询、暂停和已确认方案的人工操作仍通过相同业务规则执行。该回退可保护已有任务，但不代替 Agent 主流程验收。

### 4.1 持久化运行与业务任务的分工

本轮已应用 009—011 并接入运行记录、同计划互斥、稳定触发键去重、过期识别、方案与交易工具调用关联、退款批次关联及事件恢复。一次 AgentRun 表示一轮有界决策；确认等待或渠道等待结束本轮，后续事件关联到同一逻辑恢复事项下的新尝试，不复活内存对象。最少保存 planId、runId、父运行、触发事件／用户消息标识、状态、开始结束时间、最新业务快照版本及工具调用关联。以计划和 `(parent_run_id,event_key)` 去重，活动运行准入由服务端原子控制；进程重启后先核查旧运行与业务操作，不能只清空内存锁就重新执行写工具。

每次写工具在发送前保存稳定调用关联，重试复用同一业务请求；跨运行恢复优先查已有 confirmationId、orderId、operationId，再决定是否仍有未受理动作。不能用新的 runId 或 attemptId 作为重新建单或退款的理由。确认事件只恢复对应计划与有效确认；普通页面读取、无关业务事件不触发模型。相同 `(parent_run_id,event_key)` 只保留一个逻辑恢复事项；每个事项最多两次有界执行尝试，attempts 计数，旧运行结束为 FAILED，旧运行不能写工具，活跃观察转交新尝试。普通模型失败或取消不自动重试；有新事实时读取最新快照再解释。

### 4.2 费用预算和限流的实现顺序

项目累计 ¥100 上限按所有计划共用账本控制，同计划单运行不能代替跨计划费用控制。调用前按输入、输出上限与官方人民币费率预占费用；确认预占后才发请求，收到 usage 后结算并释放多余预占。预占规则必须覆盖本次允许的最大输出，不能只在收到结果后发现超限。人民币费率缺失或账本不可用时拒绝调用，实际配置与来源按运行文档记录。

超时或 usage 缺失不立即释放全部预占；保留待核对费用，依据可核验记录结算。每次实际重试都计入模型调用次数、费用和总时限；429 退避的等待也在 120 秒单轮上限内，超限结束本轮。令牌桶控制用户启动频率，累计预算控制费用，运行上限控制单轮工作量，三者分别检查。

先验证无资金只读工具、预算拒绝及取消，再逐项开放方案和受控写工具。网页关闭、模型失败或运行取消，只影响本轮推理；已受理交易由业务任务继续管理，不因 AgentRun 变成 CANCELLED 而取消订单。

## 六、本轮实现边界（2026-09-08）

Pi 0.85.1 两个包已精确安装并锁定。本地确定性测试验证了单工具循环、生命周期事件和未注册确认工具拒绝。`agent:smoke` 是固定虚构数据的真实模型烟测入口，最多两次模型调用、一次只读工具调用、60 秒总时限；每次输出最多 512 token、30 秒超时且禁用隐式重试。该烟测只使用虚构数据，另有 API-24 接入 T01／T02／T03／T10 与 T04／T08；两类证据分别记录。

费用账本已实现原子预占、幂等结算和未知预占保留；历史旧模型烟测按旧费率估算，并预占完整输入窗口及受限输出上界，实际估算与 usage 一起保存。当前 DeepSeek V4.1 Flash 使用官方 API 标识 `deepseek-flash`；峰值费率为缓存命中 0.04 元／百万 token、未命中 2 元、输出 8 元，闲时为高峰一半，已同步费率实现。平台账单可能变化，实际 usage 与费率版本一并记录。API-24 已实现用户令牌桶、同计划单运行、取消、截止时间、四个只读工具、两个方案工具及本轮交易工具／事件恢复接入；当前模型固定场景及进程／授权连续样本已有记录，交易、复核和恢复的剩余边界见验证策略第十七至十九节。

### 6.1 方案工具与 WAITING_USER

该方案切片当时的工具集合为 T01／T02／T03／T10 和 T04／T08。后两者复用 `proposals.ts`，分别接受 `{itemIds}` 与 `{items:[{planItemId,intent}]}`；输入不接受金额、主体、授权或确认字段。`agent_run_proposals` 保存运行、工具调用标识、输入与方案标识，一轮只写一个方案，事务成功即结束本轮并等待用户。Pi 执行前／后钩子停止同批后续动作，业务服务仍在数据库锁内复查运行状态。方案提交后取消推理不删除草稿，也不将它改写为交易成功。

页面只从持久化方案字段展示金额和范围，打开原确认卡片后由用户决定。最新运行恢复接口不发模型请求；确认后重新读取方案状态与确认标识，不重放模型写草稿。当前已保存方案和交易执行工具调用关联，确认／业务事件恢复也已接入并完成本地受控核对；当前模型固定业务场景及进程／授权连续样本已有记录，官方渠道恢复、多场景稳定性和浏览器验收仍待后续完成。429 本地退避已于 2026-09-10 补齐，见下节。真实虚构计划上的购买与变更方案联调均通过，详见验证记录第十节及第十四节。

### 6.2 显式 HTTP 429 退避（2026-09-10）

`model-retry.ts` 通过 Pi 提供的 fetch 入口重试明确 429，SDK 隐式重试仍关闭。Retry-After 支持秒数和 HTTP 日期；缺失或无效时使用 1／2／4 秒加不足一秒抖动，最多三次重试。每次实际发送单独检查运行、调用次数及费用准入；等待受总时限和取消信号约束，每次请求含流读取受 30 秒超时约束。其他 HTTP 错误、网络未知及部分流不重试。429 没有 usage 时保留原费用预占，不假定免费；后续成功只结算自身调用。费用结算在下次调用和本轮结束前等待完成，失败则停止。已完成本地受控 HTTP 与数据库验证，尚无真实上游限流联调证据。

## 七、本轮交易工具与事件恢复实现（2026-09-11）

本节记录本轮已应用 009—011 后的实现口径及剩余验证边界。工具经共用 `business-actions` 服务执行；事件恢复以稳定逻辑事项和有界尝试运行；DeepSeek V4.1 Flash 的实际 API 标识、费率与请求体已在本地核对。本节不把本地受控行为验证扩写为 S4／S5 放行，剩余验证见[验证策略第十七至十九节](../04-quality/verification.md)与[开发计划](development-plan.md)。

### 7.1 共用业务入口与工具边界

T05、T06、T07、T09 已复用 `business-actions.ts` 中的建单、付款交接、暂停及提交变更服务。HTTP 层保留会话、来源和请求幂等检查；Agent 层绑定运行、计划和工具参数。两者进入同一业务服务后，仍在事务内检查权限和当前事实，不能因为上一层已经检查过就省略。

| 工具 | 采用参数 | 服务端必须决定的内容 | 返回给模型的内容 |
| --- | --- | --- | --- |
| T05 create_order | `confirmationId`、`planItemId` | 确认类型和归属、有效购买授权、项目范围、最新报价与规则、暂停状态、累计预算；已有订单优先复用 | 订单、操作、环境及受理状态；不宣称付款成功 |
| T06 request_payment | `id`，即订单标识 | 当前计划归属、订单环境和付款状态；生成新交接前复查购买授权及暂停范围 | 模拟订单返回已有处理状态；沙箱订单返回订单引用和需用户操作的说明，不返回签名链接或付款会话 |
| T07 pause_purchases | 空对象 | 读取本轮已认证用户的原始消息，核定明确暂停范围；事件恢复和外部文本不能提供这一指令 | 暂停范围、生效版本与在途订单清单；不把暂停解释为关单或退款 |
| T09 submit_change | `id`，即变更方案标识 | 确认、善后授权、逐单范围、当前付款／退款事实和商户规则；重复返回原操作 | 任务标识和受理状态；商户退款批次执行权不下放 |

T05 逐项建单是现有 API-05 的直接映射，不让模型提交价格、商户或预算替代服务端计算。报价变化时必须重新预览与确认；生成新预览也要读取当前报价，不能继续使用计划项的旧展示金额。已有订单应读取原事实，不为了绕开旧授权或异常状态再次建单。T06 即使返回交接已准备，用户仍须在付款页面进入官方收银台完成必要操作。

局部暂停应只限制选中项目。若直接将覆盖整个计划的购买授权标记为暂停，会连带阻止未选中项目，违背既有局部暂停规则；实现应以计划项暂停范围控制准入，并与整体暂停、重新确认后的新授权保持一致。已发出的付款与已受理善后继续核对，暂停不抹除它们。

### 7.2 明确暂停的保守识别

当前支持完整且明确的本轮指令，例如“暂停全部购买”“暂停 A 的购买”，由服务端根据当前计划的项目名称或目录代码解析范围。工具参数不接受模型补写的用户请求、项目列表或所谓确认记录。

商品说明引用、否定句、条件句、含糊的“取消一下”以及无法唯一定位的项目均不自动暂停；返回澄清提示并保留独立按钮。正则或词组匹配只是首个受限入口，不能标记为完整自然语言意图理解。T07 使用空对象输入，只从本轮原文明确暂停；同轮不同 callId 也复用第一次结果，不能依赖模型每次生成相同 toolCallId 才避免重复版本更新。

### 7.3 区分恢复原因，而非恢复一段旧对话

| 触发原因 | 允许的行为 | 明确限制 |
| --- | --- | --- |
| 本轮用户消息 | 读取事实、生成方案；按既有真实确认受控执行；明确暂停须另核原文 | 聊天中的“确认”不创建授权；工具可见不代表业务准入通过 |
| 用户确认助手生成的方案 | 从最新快照继续这一确认对应的建单／付款交接或提交变更 | 不能执行其他确认、生成新方案、代替用户付款或新增暂停指令 |
| 关联订单出现新事实 | 读取最新业务快照，解释已发生结果、未决金额、责任和下一步 | 只开放只读工具；不能据此发起新交易或受托渠道查询 |
| 页面刷新或重复观察同一事实 | 读取持久化运行和业务状态 | 不启动模型 |

恢复提示应引用服务端保存的确认和事件标识，不把外部事件正文当成指令。运行层根据触发原因缩小工具集合，业务层再次校验触发事件及对象范围；只在提示词里要求“不要越权”不足以构成隔离。普通用户消息的 T10 显式复核已补齐受控 Pi 链及真实模型局部执行证据（验证策略第十四节）；事件恢复不得使用该参数，仍只读最新快照。

### 7.4 等待、取消与费用

确认等待或业务等待结束本轮推理；后台处理交易任务不持有模型会话。事件恢复也须遵守同计划单活动运行、入口限流、调用次数、120 秒总时限和共享人民币预算。进程中断或过期最多产生两次有界子运行尝试，每次递增 attempts 并保留旧运行为 FAILED；普通模型失败或取消不自动重试。预算不足、模型失败或取消不能删除已有交易任务。

“停止本次助手跟进”与“撤回授权”继续分开。取消 API 取消目标及其后代仍处于待运行／等待状态的运行，关闭该分支队列与订单观察；不删除订单，不撤销已受理业务。不能仅检查最早父运行的状态，也不能把查询授权撤回等同于删除已知事实。页面应分别显示推理是否结束、交易是否仍等待；业务已终态但摘要失败时，交易结果仍可通过结构化页面读取。

### 7.5 尚需收口的实现判断

工具调用记录需要承担可追溯性，业务唯一约束承担跨运行去重；新的 runId 或 toolCallId 均不能成为重复建单、重复提交或重复占用预算的理由。事件去重、中断接管、订阅建立时已经终态以及父子运行结束状态，应按[数据与事件第五节](data-and-events.md)统一。页面说明可以先明确产品行为，但在真实模型与官方渠道恢复链未验证前，不能把“将继续处理”的文案当成完整链路已通过的证据。

### 7.6 真实模型局部评测后的工具信息调整（2026-09-12）

针对实际观察到的单位换算和已确认方案提交问题，T02 额外返回 `displayAmounts`：预算上限、已支付净额、占用、剩余额度及订单实付／已退金额均由现有金额函数格式化为人民币元，原始 Minor 字段仍以分计。`budget.paidMinor` 是实付扣除已确认退款后的净额，不能解释为历史付款总额。已确认变更记录额外提供 `submitChangeInput: { id: proposalId }`，T09 描述要求原样使用该参数，不能用确认号或订单号替代；该提示不授予执行权限，业务服务仍复查当前确认和授权。

用户明确请求生成草稿且对象、意图清楚时，直接生成并交由独立确认卡片审核，不在草稿前再索要口头确认。订单已有取消处理或退款事实时，T03／T08 不再生成新的报价或取消草稿；助手重读原取消申请、已退与待退批次和人工责任，说明当前进度。查询续期不重新取消，原确认的重试仍复用已有操作。暂停购买不阻止已有订单的善后草稿。模拟 T10 受理说明明确由本订单商户人工跟进，不访问官方渠道；消费者取消申请同时显示关联订单层面的人工责任。以上调整有受控链和真实模型局部证据，不宣称自然语言解释已经完全稳定。


### 7.7 确认恢复与结果解释补充（2026-09-12）

购买确认事件的输入明确要求为确认项创建或复用订单，再逐单调用 `request_payment`；本次确认范围内不重复索要口头同意。模拟订单只读取后台付款状态，沙箱待付订单才准备用户付款交接。变更确认事件明确使用本次 proposalId 提交，商户继续独占退款执行。

T02 `confirmedActions.linkedOrders` 返回购买确认已经产生的订单及当前状态，避免把确认的 `confirmed` 状态或购买授权空 `orderIds` 误解成尚未建单。写工具执行后，模型须重读快照再解释预算和状态；方案状态不替代实际订单、取消与退款事实。该提示是解释约束，授权、幂等和确认隔离仍由既有业务层保证。历史真实模型连续模拟交易与最后的购买摘要复测见[验证记录第十五节（旧模型）](../04-quality/verification.md)，当前模型固定场景及解释修正见第十八节，均不代表官方渠道或多场景解释质量通过。

当前模型集中评测见[验证记录第十八节](../04-quality/verification.md)。助手须与既有购买准入保持一致：已有订单的计划项即使已取消或全退，也不能再生成购买方案，不能建议用新确认或提高上限绕过。模拟成功只说明模拟记录，不表述为真实资金到账；退款不参与剩余购买空间的加减。明确暂停可走受控暂停工具，无需购买或变更确认卡片。以上仅修正解释指引，不改变业务准入或新增工具。

真实模型进程中断及授权撤回／续期／到期固定场景见[验证记录第十九节](../04-quality/verification.md)。授权失效时说明用户已提出请求但不能受理，不否认明确的复核请求；取消申请的 `pendingRefundMinor` 仅表示已建未完成批次，已批准但未退金额按 `acceptedRefundMinor - refundedMinor` 解释，不能把尚未建批次误报为无需退款。
