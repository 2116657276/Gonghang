## 一、运行原则

每个会话只有一个活动决策循环。Pi 使用本项目定义的工具集合，不提供 shell、任意 HTTP、文件写入或商户原始退款工具。工具返回结构化事实与来源，模型负责解释；文字“确认成功”不能取代用户确认接口。

Pi 上游已有工具循环、事件与执行钩子；其会话能力不是交易账本。上游仓库当前有迁移与命名变化，选定发行版前核对包名、许可证、运行时和恢复语义，见[证据登记](../05-research/evidence-register.md)。

## 二、工具目录

| 工具 | 输入 | 输出 | 控制 |
| --- | --- | --- | --- |
| T01 search_catalog | 类别、日期、需求约束 | 商品、价格与规则引用 | 只读；价格由商户返回 |
| T02 get_plan_orders | 当前计划标识 | 可访问的订单、付款与退款快照 | 只读；后端绑定用户 |
| T03 get_cancellation_quote | 订单标识 | 可退金额、费用、有效期与规则版本 | 只读；不等于批准退款 |
| T04 propose_purchase | 商品标识、数量、选择理由 | 服务端计算的购买方案及确认卡片 | 写草稿；不产生购买授权 |
| T05 create_order | 已确认方案标识 | 订单或冲突原因 | 写操作；重查授权、报价及预算 |
| T06 request_payment | 订单标识 | 受控付款交接引用或既有处理状态 | 写操作；秘密链接不回灌模型 |
| T07 pause_purchases | 计划或节点范围、用户请求关联 | 生效版本、暂停范围、在途清单 | 服务端核对明确用户指令；有独立按钮入口 |
| T08 propose_change | 订单范围、保留与取消意图 | 变更方案、费用及待确认卡片 | 写草稿；服务端查规则和快照 |
| T09 submit_change | 已确认变更方案标识 | 处理任务与受理状态 | 写操作；逐订单检查，不直接暴露商户退款 |
| T10 get_operation_status | 已有操作标识 | 状态、来源时间、责任与后续动作 | 只读；按权限与渠道限频使用缓存或查询任务 |

用户确认接口不是 Agent 工具。商户退款执行同样不在此目录。T07 不允许仅因外部商品文本要求暂停而生效；自然语言含糊时澄清，独立按钮路径完全不经过模型。

## 三、循环与等待

运行状态为 READY、RUNNING、WAITING_USER、WAITING_EXTERNAL、COMPLETED、FAILED 或 CANCELLED。它们只表示 Agent 运行，不表示订单与退款终态。需要确认时持久化方案并结束本轮；收到有效确认后从最新业务快照开始下一轮。需要渠道核对时交给后台任务，不在内存中无限等待。

模型调用前注入已认证范围、当前计划、有限的订单快照、未决操作、规则来源和当前允许工具；不注入密钥、验证码或付款会话。摘要可压缩聊天，不能压缩掉方案版本与操作关联。恢复后重新读取业务事实，不照着旧摘要重放写工具。

## 四、执行控制

独立只读查询可以并行；同一授权和订单的写操作受控串行。Pi 的执行前钩子用于快速拒绝，但业务服务必须再次验证身份、授权、参数、金额、环境和幂等。不同会话和后台执行者的并发靠数据库规则，而不是单循环假设。

所有工具使用运行时字段校验。失败返回明确类别、是否可重试和既有操作标识；结果未知时返回待核对，不诱导模型改参数重试。超出模型轮次、调用次数、费用预算或运行时限后停止决策，保留任务并提示用户；参数需评审后固定。

取消 Pi 运行只取消尚可取消的推理或本地工具等待，不代表已经发出的外部调用被撤销，也不删除已受理任务。即使模型不可用，查询、暂停和已确认方案的人工操作仍通过相同业务规则执行。该回退可保护已有任务，但不代替 Agent 主流程验收。

## 五、验证重点

A03 验证部分保留，A09 验证外部文本不取得权限，A11 验证模型不能确认或改价，R11 验证恢复，R12 验证限额与模型失败。评测记录模型、Pi 版本、提示词修订标识、工具集合、输入、结果与费用；比较时保持商户规则一致，不把换模型效果当运行框架效果。
