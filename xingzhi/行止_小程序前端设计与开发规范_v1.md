# 1. 产品定位与设计目标

## 1.1 产品定位

“行止”是一个围绕**资金安排、计划管理、账目查看与 AI 辅助决策**展开的微信小程序。

它不是传统记账 App，也不是纯聊天 AI 产品，而是：

- 用 **首页** 展示用户当前整体资金状态；
- 用 **计划页** 管理未来计划；
- 用 **行止 AI** 解释、整理、分析、联动操作；
- 用 **账目页** 展示已经发生的事实；
- 用 **我的页** 管理账户、授权与设置。

## 1.2 设计目标

本次 UI/前端设计目标如下：

1. **轻量但专业**：避免传统银行风、避免过亮的“嫩绿”，整体更克制、更高级。
2. **层级清晰**：核心信息第一眼可见，复杂操作下沉。
3. **统一视觉语言**：五个一级页面共享同一套设计 Token。
4. **适配微信小程序**：考虑小程序页面性能、滚动、弹层、TabBar、状态栏安全区域。
5. **支持 PC 调试**：前期可以在浏览器/H5/开发工具中测试，但最终发布目标是微信小程序。
6. **对 AI 友好**：文档中明确结构、配色、间距、状态、交互和跳转，降低歧义。

# 2. 技术栈与开发约束

## 2.1 技术栈

- **框架**：Taro 4.x
- **UI 框架**：Vue 3
- **语言**：TypeScript
- **样式方案**：SCSS / CSS Modules（二选一，推荐 SCSS + BEM 命名）
- **状态管理**：优先轻量化 `composables + service`；不要一开始引入重型状态管理库
- **网络请求**：统一封装 `request.ts`
- **运行端**：微信小程序（主），H5（辅助调试）

## 2.2 开发工具建议

### 推荐工具链

- **VSCode**：主开发工具
- **微信开发者工具**：小程序编译、调试、预览、真机
- **Node.js / pnpm 或 npm**：依赖管理
- **HBuilder**：可作为视觉参考或简单原型辅助，不作为 Taro 主构建工具

### 说明

虽然用户可以使用 HBuilder，但本项目正式技术栈是 **Taro + Vue + TS**，因此：

- **代码编辑与构建推荐 VSCode + Taro CLI**；
- **最终预览与真机验证必须通过微信开发者工具**；
- HBuilder 不参与正式构建链路。

## 2.3 前端约束

1. **前端不重算核心业务结论**。例如：
   - 不自己推算最终是否“可以买”；
   - 不将预计工资直接算入可用余额；
   - 不将退款待到账直接算为已到账；
   - 不把 `unknown` 错当成“可执行”。
2. 所有状态结论以后端返回为准。
3. 前端负责：
   - 展示；
   - 格式化；
   - 交互引导；
   - 跳转与确认；
   - 轻量 UI 级弹层。
4. 真实动作（购买、预算确认、退款申请、调整确认等）必须跳入结构化确认页面或确认流程。

# 5. 全局毛玻璃与背景设计规范

## 5.1 毛玻璃使用范围

### 可以使用毛玻璃的地方

1. 首页顶部 Hero 区背景浮层
2. AI 页面顶部上下文卡
3. 浮动 AI 助手卡
4. Bottom Sheet 顶部标题区
5. 小型浮动提示条（如风险说明、状态提醒）

### 不建议使用毛玻璃的地方

1. 所有列表项都做毛玻璃
2. 文本信息特别密集的主列表内容区
3. 账目列表整屏大面积毛玻璃

## 5.2 毛玻璃参数建议

```css
background: rgba(255,255,255,0.56);
backdrop-filter: blur(20px);
-webkit-backdrop-filter: blur(20px);
border: 1px solid rgba(255,255,255,0.38);
box-shadow: 0 8px 24px rgba(31, 66, 54, 0.08);
```

### 小程序注意事项

微信小程序对 `backdrop-filter` 兼容性不稳定，因此：

- **H5 / PC 调试端**：可开启真正毛玻璃；
- **小程序端**：降级为“半透明白底 + 浅描边 + 阴影 + 浅渐变”。

也就是说必须实现一个**可降级毛玻璃风格**：

```text
H5：真实 blur
Mini Program：伪毛玻璃视觉
```

## 5.3 页面背景风格

所有一级页面都采用统一风格：

1. 页面顶部 Hero 区有淡绿色山丘/树木插画式背景；
2. 底色保持浅灰绿；
3. 内容区卡片为白底或浅毛玻璃白底；
4. 底部 TabBar 独立，不叠加大面积复杂背景。

## 6.2 页面滚动规则

- 一级页面内容区单独滚动；
- Hero 区固定在顶部，内容向上滚动覆盖；
- 浮动 AI 卡在首页滚动时可缩小为角落悬浮按钮；
- TabBar 固定底部。

## 6.3 按钮层级

### 一级按钮

- 实心品牌渐变按钮
- 用于：提交、前往确认、创建计划、查看详细分析等高优先级动作

### 二级按钮

- 浅底描边按钮
- 用于：关闭、次级跳转、查看更多

### 文字按钮

- 纯文字 + 箭头
- 用于：轻跳转、查看全部、查看详情

## 6.4 标签 / 状态规范

| 状态 | 颜色 | 文案风格 |
|---|---|---|
| fits / allowed | Success | 符合当前约束 |
| requires_change | Warning | 当前需要调整 |
| conditional | Info | 依赖预计收入 |
| unknown | Neutral / Info | 当前信息不足 |
| blocked | Danger | 当前无法继续 |

## 6.5 图标规范

推荐使用：

- 线性图标为主
- 单色或双色低饱和图标
- 重要状态可以使用小圆点/小盾牌/小箭头

推荐图标场景：

- 首页：账户、未来30天、风险、计划、账目
- 计划页：餐饮、活动、购物、草稿、调整
- AI 页：上下文、对话、建议、计划卡
- 账目页：支出、收入、退款、未来义务
- 我的页：账户、设置、安全、历史、退出

# 15. 状态、空状态、异常状态规范

## 15.1 空状态

### 首页无主账户
- 显示“选择主账户后，行止才能帮你判断资金影响”
- 主按钮：`选择主账户`

### 计划页无计划
- 显示 IP 插画 + “这个月还没有计划”
- 主按钮：`创建第一个计划`

### 账目页暂无账目
- 显示“还没有账目记录”
- 次按钮：`返回首页看看`

### AI 页无会话
- 显示快捷问题和 IP，引导发起第一句提问

## 15.2 加载状态

- 采用骨架屏，避免全页大转圈
- 骨架结构应贴合真实卡片结构

## 15.3 异常状态

### 网络错误
- 标题：`暂时连接不上`
- 操作：`重新加载`

### unknown 状态
- 不是报错
- 文案：`当前信息不足`
- 颜色：灰蓝 / 中性

# 19. 给 AI 生成前端代码时的明确约束

以下规则可直接用于后续喂给 AI 生成代码：

## 19.1 不可偏离的设计要求

1. 技术栈必须是：
   - **Taro + Vue 3 + TypeScript**
2. 页面必须是微信小程序风格适配，最终以微信小程序发布为目标。
3. 配色使用本文件中的**升级版高级配色方案**，不得继续使用过亮的嫩绿色。
4. 页面必须采用：
   - 淡绿色 Hero 背景
   - 白色/伪毛玻璃卡片
   - 轻阴影
   - 大圆角
5. 所有一级页面都必须使用统一底部 TabBar：
   - 首页 / 计划 / 行止AI / 账目 / 我的
6. 首页、计划页、账目页、我的页必须按照本文件给出的页面组织结构实现。
7. AI 页面必须采用：
   - 上下文卡
   - 快捷问题
   - 聊天流
   - 结构化结果卡
   - 底部输入栏
8. Bottom Sheet 统一采用半屏样式，不要滥用居中弹窗。
9. 小程序端毛玻璃必须提供伪毛玻璃降级方案。
10. 不得引入与文档冲突的强色、高饱和荧光色、复杂运营 Banner 风格。

## 19.2 代码实现建议

- 颜色、圆角、阴影、间距必须抽成全局 SCSS 变量；
- 通用卡片组件必须可复用；
- 页面中的状态样式必须通过枚举控制；
- 所有跳转使用统一封装的 router helper；
- Bottom Sheet 统一组件化；
- 禁止把页面写成一个超大文件，应拆组件。

## 19.3 视觉实现注意点

- 所有大卡的留白必须充足；
- 金额字号大于普通正文；
- 状态颜色要低饱和，避免“刺眼”；
- 列表内容区尽量白底，毛玻璃只用于强调层；
- Hero 背景始终比内容区更淡；
- 所有按钮文案尽量用明确动作句，而不是“确定”。

## 19.4 页面最关键的交付验收点

- 首页：摘要清晰、AI 卡自然、风险提醒明确；
- 计划页：状态分组清晰、卡片层级明确；
- AI 页：像“懂业务的对话工作台”，不是普通聊天框；
- 账目页：历史事实与未来义务严格分开；
- 我的页：管理感强但不沉重；
- 全局：统一、克制、带高级感。
